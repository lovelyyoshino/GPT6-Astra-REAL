本次新 RGB 显示充电器插脚完全离开原插孔，最后有效录像中仍由左夹爪夹持。右臂未接收这轮单臂任务指令。后续要求的额外 10 cm 上提没有完成：两次有效上提后的控制器法兰 Z 净增约 9.383 mm，随后 J5 回报 `motor_overheating` 和 `driver_error_status`，新增动作被拒绝。故障时记录的电机/驱动温度约为 42/47°C，不能单凭标志断言真实过热原因。未执行释放或移插，不声称已经验证物理停止。

## 核心修复

| 问题 | 当前实现与边界 |
| --- | --- |
| 实体为 PiPER X，但更换/刷写后的控制器使用普通 PiPER 位姿 | 保留 X 型号；显式、限时、绑定启动身份的旧控制器坐标兼容，另检查 X 模型运动包络。提供经用户指定的 1/2.5/5 mm 向上档位，仍为逐段监督目标。 |
| J5 被旧 PiPER 的 ±70° 软件交集拒绝 | 只在独立左侧查询确认本机 ±89°、旧失败完整审计后，使用 X 与本机限位交集；其它轴和物理约束保持。查询不会改写控制器参数。 |
| 端点计算消耗了反馈有效时间 | 单次预测最多 1 秒，计算后获取新完整反馈并重新检查起点及模型范围；发送前反馈年龄仍为 100 ms。 |
| 上一次稳定回执之后关节仍有细小收敛 | 下一提案采用新被动反馈；精确审计已知零发送旧参考拒绝，不追认旧失败或重发旧目标。 |
| 只用左爪却被右爪置零失败阻塞 | 普通夹持帧可同时使能选中爪，不要求置零；失能且禁止发送的对侧保留有符号开口读数。仅隔离已审计的对侧维护失败，新的硬件故障仍拒绝发送。 |
| CAN 多帧拼接及接续状态不一致 | 完整分帧组、原始时间戳、共享有界反馈档、持久动作登记与累计预算；配套启动归档、角色投影和接触回执修复一并纳入，避免只提交兼容层而缺少依赖。 |

入口与回执合同见 [TOOLS.md](../../projects/piperx_cloth_demo/docs/TOOLS.md)、[PAIR_HOST.md](../../projects/piperx_cloth_demo/docs/PAIR_HOST.md) 和 [优化记录](../../OPTIMIZATION_GUIDE.md)。默认分发配置不携带此次启动身份、用户授权窗口和失败审计引用；现场配置保留在原工作区。源码可复用不等于旧任务可以自动重放。
