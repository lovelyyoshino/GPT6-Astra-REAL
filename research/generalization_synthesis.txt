复用同一软件流程，因此将两个旧工程的经验放入任务合同、有限操作、

本地共用结构
./astra 是离线入口：catalog / plan / session / replay / evaluate / experiences。
L3 recipe 固定目标、初态和有限阶段；角色与总预算由任务 session 冻结。
阶段允许 goal、附加 evidence、max_cycles 和 arm；操作前提继承注册表，
recipe 无全局 budget 字段，也不能重写前提。L2 描述当前操作；
L1 负责动作边界和回执；L0 保留具体 Piper 适配及原有安全层。
模型只接收当前必要 RGB 与短状态，不重复完整旧任务历史。

初始配方：tasks/pen_in_holder.json、can_on_lid.json、
charger_in_unpowered_socket.json、turn_faucet.json、sort_two_objects.json。
最后一个通过有限次数的双对象抓放展示复杂组合。新增 place_on_support
和 articulated_rotate 避免把原支撑/螺纹判据误套到杯盖/水龙头。
通用配方全部 offline_contract_only / execution_available=false，
不静默接到现有单右臂 pen runner，不因为 JSON 能表达就宣称实机可做。

持久 session 保存冻结合同、revision、唯一事件和累计预算。恢复、重启
与观察分支不能清总预算；观察视野改善不清工臂无进展。数据库保证
记账一致性，不认证用户提交的回执真实性或取得设备互斥。

经验检索是静态已审卡片，最多两张，与当前状态分栏；卡库和源证据都
做哈希核查。新增内容来自笔、充电头、空罐和 timeout 记录。卡片不含
历史动作坐标、当前授权或安全豁免，不产生额外模型请求。

评估采用声明式 facts、前后依赖、观察数量和稳定时间窗口。模型视觉
报告、独立 RGB 审核、模拟器 oracle 分开；运动到位不能代替物体证据。
后续命令/人工改变后旧终态失效，需要新稳定窗口。结构审核不认证像素、
真实不同帧或 reviewer；上层冻结 claims，采集/审核宿主负责事实来源。
合成 JSON 回放只验证接口；缺证据维持 null，不能记为真实成功或失败率。

两套旧工程的可复用教训
笔入筒：监督成功保留；容器变体与侧面人工指导写进结果，不混作全自主。
充电头：抓起与插入目标分开；实际物体轴不能由工具欧拉角替代。
空罐：独立支撑通过松爪撤离后新图验证；人工确认杯盖属于人工元信息。
反复细调：局部目标和有限预算约束无进展，不追逐历史角度或无限换视角。
timeout：退出、断连、失能不是停止保证；保留原事故与未解决资格。
未知发送：命令请求、驱动接受、完成反馈和任务成功是不同事件。
零发送拒绝：与发生过运动的失败分开，但不删原记录、不自动洗掉锁存。
录像：任务开始/结束、分段和缺口明确记录；裁剪原速片段不是整轮耗时。

后续复杂任务的开发顺序
一，固定可观察目标、初态/人工前置和角色，选择或新增有限 recipe。
二，离线校验 schema、步骤、证据、持久化与预算；加入失败和重开回归。
三，保留旧基线，用小范围候选修改和独立 agent 校对，不引入新定位先验。
四，需要新实体技能时另做适配与实际停止/路径验证，保持原数值约束。
五，在一致任务与现场条件下运行新试次，分别记录时间、调用、人工介入、
     成功、回位与录像。不用合成回放时长估计真机提速或成功率。
