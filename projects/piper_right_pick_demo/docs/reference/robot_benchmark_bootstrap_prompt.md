# 独立搭建 GPT 机器人测评项目的 Prompt

将下方“给 Codex 的指令”整段交给 Codex，并附上你们已有的设备、SDK 和部署资料。本文包含搭建要求与接口约定，不依赖原项目源码。

## 给 Codex 的指令

你是一名机器人软件工程师。请在当前工作区创建一个独立的 GPT 机器人操作测评项目，重点支持真机接入，并为仿真对照保留适配能力。请直接生成项目文件，不只输出方案。

使用本说明、用户提供的资料和厂家公开文档独立实现。不要要求访问任何原始内部仓库，不复制其源码，不引入其路径、私有模块、账号或服务地址。

### 项目目标

实现以下闭环：

**任务指令＋相机观测＋机器人状态 → GPT 决策 → 动作检查与转换 → 机器人执行 → 新观测与执行反馈 → GPT 再次决策。**

任务评分和过程记录贯穿运行，结束后生成报告与录像。

GPT 自主决定接近、抓取、搬运、释放和纠错。底层负责坐标变换、IK、运动执行和状态回读。不要将完整任务预制为抓取脚本，再让 GPT 只选择脚本。

GPT 通过远程接口调用，不要求本地部署模型。模型 ID、接口地址和请求协议使用用户实际提供的值；尚未提供时留为必填配置，不猜测可用型号或地址。

### 参考设备与待确认信息

参考方案为 ARX／方舟 R5 双臂、两指夹爪、一个第三视角相机和两个腕部相机。参考相机为奥比中光 Gemini Pro 与 Gemini 305，控制链路有 200 Hz、CAN 通信的需求。以上仅作为起点，最终以接收方实际设备及厂家资料为准，不把参考值直接认定为真机参数。

先读取当前工作区已有资料，整理下列信息的“已确认／待确认”状态：

| 信息 | 对实现的影响 |
| --- | --- |
| 机械臂、夹爪的准确型号与版本 | 机器人描述、关节顺序、自由度、运动范围、夹爪映射 |
| 操作系统、CPU 架构、Python 与 SDK 版本 | 安装环境、动态库和驱动兼容性 |
| SDK 示例、控制模式、状态反馈 | 能发送关节目标还是末端目标，如何判断执行结果 |
| CAN 设备、接口名与控制周期 | 真机通信和持续下发方式 |
| ROS 使用情况及版本 | 是否通过 ROS 集成、已有话题和坐标变换 |
| 相机型号、序列号、接口与深度支持 | 视角绑定、图像同步、深度读取 |
| 相机标定、两臂底座变换、关节零位与 TCP | 图像定位、坐标转换和运动学一致性 |
| 可用物体、工作区域与复位方式 | 首个任务与成功标准 |

缺少设备信息时，继续完成不依赖这些信息的核心框架、离线运行和明确的适配接口。不要用猜测值伪装已完成的硬件适配；未知项在真实执行前给出具体错误。仿真临时参数与真机参数分开存放并标注来源。

### 架构与代码组织

采用 Python `src/` 布局。将任务、模型接口、机器人适配、相机、运动控制、执行循环、评分和记录分离，模块之间使用明确的数据结构。

- 核心框架不在导入时加载 Isaac Sim、ROS 或厂家动态库；按运行后端加载可选依赖。
- 任务通过注册表关联配置、场景或现场准备要求、复位和评分逻辑。命令按任务名称解析，不在主入口逐个堆积任务判断。
- 用 TOML 或同等清晰的配置方式管理任务、机器人、相机、模型和运行预算；每次运行保存实际生效配置。
- 提供 Conda 环境说明，将核心依赖与真机／ROS／仿真依赖分开。兼容路径配置，不写入开发者个人目录。
- 集成检查入口集中放在 `integrationtest/`；单元测试放在 `tests/`。
- 模型凭证通过环境变量读取，默认变量名为 `OPENAI_API_KEY`。日志不记录凭证，本机配置、运行产物和下载缓存不进入版本管理。

不要为尚未提出的机器人型号或任务建立大量空模块。首版围绕 R5 和一个简单任务完成有实际功能的框架。

### 共同接口约定

| 模块 | 输入／输出约定 |
| --- | --- |
| 观测 | 任务指令、相机名称、图像、采集时间、实测机器人状态、上一步执行反馈；深度和标定按配置启用 |
| 模型动作 | 指定机械臂、末端目标位置与朝向、夹爪开口；支持等待、停止和可选的简短动作说明 |
| 执行反馈 | 接受／拒绝／执行中／到位／超时／故障；附目标与实测差异、时间和原因 |
| 任务评分 | 成功／失败／未评估、过程指标、终止原因、评分依据；与模型可见观测分离 |

长度统一为米，关节角统一为弧度，内部四元数统一为 `w, x, y, z`。如果厂家或模型接口使用其他约定，在边界显式转换。

明确世界坐标、各臂底座坐标、相机坐标和 TCP 坐标。TCP 是夹爪上的控制参考点，与厂家末端法兰可能存在固定偏移；不能混用二者。夹爪接口表达两指总开口，按实际标定映射到厂家单位。

动作协议要求确定、可解析，检查字段、单位、数值、机械臂权限和边界。非法响应不执行运动，把原因反馈给模型，并计入已经发生的模型调用。停止请求只表示结束决策，成功由评分器判断。

### 相机与模型输入

为第三视角和两个腕部视角设置稳定名称，绑定实际设备，避免依赖插入顺序。保留采集时间，限制不同视角和机器人状态的时间偏差；过时数据应明确标注或重新采集。

默认提供 RGB 与实测机器人状态。深度、内外参和图像辅助标记均作为可配置输入，不把不存在的传感器信息提供给模型。

启用深度时，明确其单位、无效值和距离定义，并保证与 RGB 对齐。可提供深度预览，以及按图像像素查询可见表面三维位置的只读接口。查询结果不直接等同于物体中心或抓取目标。深度查询同样占用模型调用预算。

真机相机使用实际标定，并标注标定版本；仿真使用当前虚拟相机参数。不能把仿真内外参或理想深度当成真机测量。

模型每次接收当前采样图像、任务和反馈。文字历史与图像历史分别管理，图像保留数量可配置；新独立回合清空历史。可要求模型附简短观察与动作目的，记录在日志中，不要求输出详细思维过程。

### 真机 SDK、IK 与 ROS

先阅读厂家对应版本的文档和示例，再编写适配，不编造 SDK 方法名、ROS 话题或驱动参数。

**SDK 负责设备通信和实际控制。** 封装连接、状态读取、目标下发、运动状态和错误反馈；使能、停止和恢复行为依据厂家接口实现。优先使用现有 SDK／驱动，不另行猜测 CAN 报文协议。

**IK 负责末端目标到关节目标的转换。** 根据已确认的 SDK 能力选择：

- SDK 提供经过验证的末端控制：优先调用该接口，确认其坐标、插值与到位语义。
- SDK 只接收关节目标，但提供可调用的逆解：优先使用对应机器人版本的逆解。
- 需要独立求解器：使用准确的机器人描述、关节限位、零位和 TCP 配置实现，并检查解的误差。Isaac Sim 后端可以使用 Lula；不要因此要求真机控制必须依赖 Isaac Sim。

IK 成功不代表运动路径无碰撞。保留运动边界与轨迹执行职责；只有接入并验证了路径规划器，才能声称具备自动避障规划。

**ROS 是可选的集成方式。** 对方已有 ROS 时复用其相机、状态、控制和坐标变换接口；能够通过 Python SDK 直接实现时，不强制引入 ROS。ROS 1／ROS 2 的选择以实际驱动支持为准，不同时维护两套重复业务逻辑。

资料不完整时，为硬件边界实现清晰的未配置错误；离线模拟适配器必须单独命名，不能在真机模式中静默回退。

### 执行时序与控制

将 GPT 决策循环与设备持续控制分离。若设备确认要求 200 Hz 下发，由 SDK、驱动或本地控制循环承担，不让每次下发等待模型接口；记录实际周期与超时情况。

仿真可以暂停物理等待 GPT，真机仍受重力和接触影响。真机等待期间由底层控制器按设备支持的方式保持控制，继续读取状态；新动作执行前检查观测是否过时。

为目标设置有效期、关节及工作范围限制、运动速度限制和通信失联处理。停止策略依据设备能力配置，不能将模型超时默认处理为松开夹爪。

末端目标经过检查与坐标转换、IK 或厂家末端控制后执行，依据实际位置误差和稳定状态判断到位。为单动作设置执行上限；超时后反馈实测状态，不伪造到位。

移动与夹爪开合的先后关系明确配置，首版可采用先到位再开合。夹爪被物体挡住而未达到空载开口，不应自动等同于抓取失败。夹爪位置控制也不能宣称为经过标定的夹持力控制。

### 首个任务与评分

首版只实现 **GPT 单臂方块抓放**：使用指定机械臂自主抓起方块，搬运至目标区域，释放并撤离，另一臂保持静止。

任务参数包括物体尺寸、初态、目标区域、最低抬升高度、放置误差、稳定时间、调用及时间预算。真机未知参数标为待配置，不照搬仿真工程值。

成功需有抓取抬起、搬运、释放和稳定放置的证据。不能以机器人末端到达目标、GPT 宣称完成或物体被推到目标区域作为完整成功。

仿真评分可使用物体状态和接触信息，这些评分真值不泄露给模型。真机评分根据现场可用的视觉测量、传感器或人工复核实现，记录证据来源；缺少必要证据时标为待复核或未评估，不使用伪造的物体状态。

仿真与真机分别统计，注明输入、动作接口、时序和评分测量的差异。对齐协议有助于比较，但不能直接声称两者物理能力等价。

### 复位、预算与错误处理

将新独立回合与同一回合中的重试区分：

- 新回合使用新的记录目录和空模型历史，记录初始条件。
- 重试只有在任务定义了可重试条件且策略启用时进行；可以保留历史，但共享调用和时间预算，记录失败原因与复位次数。
- 真机复位依据现场实际方式执行，可以需要人工恢复物体；确认恢复完成后再继续，不能像仿真一样直接写物体位置。

分别管理模型调用上限、单动作执行预算、整场现实时间上限；仿真另有物理推进预算。达到成功、停止条件或不可继续的故障时可以提前结束，不强制用满调用次数。

模型额度、网络、设备故障与任务失败分别记录。保留已产生的调用、耗时与过程证据，不把未完成评估的服务故障自动算成模型操作失败。

### 记录与 token 统计

每个回合将配置、模型版本、指令、观测、动作、反馈、评分、录像与报告保存在同一独立目录，避免覆盖旧记录。失败过程同样保留。

从模型服务实际返回的 usage 中记录每次调用的输入、输出、缓存和推理 token，并汇总到回合与任务。缺失用量标为未知，说明统计覆盖率，不按零处理。按服务商字段定义区分包含关系，避免把已经包含在输入／输出中的缓存或推理 token 再次相加。

记录模型调用次数、接口等待时间、实际运行时间，以及仿真时间或真机运动时间。费用只有在明确服务商计费规则后才估算，并标注口径。

报告列出成功判定依据、阶段进展、动作拒绝、超时、重试和典型失败。区分首次尝试结果与保留历史重试后的最终结果。

### 实现顺序与交付

按依赖顺序推进：

1. 建立配置、数据协议、任务注册与公共执行循环。
2. 实现独立的离线模拟／回放适配器，使无设备、无凭证时也能运行流程，并明确标为非物理、非任务成功验证。
3. 实现模型调用、观测打包、动作解析、历史管理和 usage 记录。
4. 根据真实资料实现相机及机器人 SDK 适配，再接入坐标转换、IK 和持续控制。
5. 实现首个抓放任务、评分、记录与报告；需要仿真对照时，再接入可选的 Isaac Sim 后端，复用公共协议。
6. 提供与上述关键行为对应的离线测试，以及集中管理的集成检查入口。

提供一份简洁 README，说明安装方式、配置项、各模式启动方式、当前实现状态与待补齐信息。接口文档应让另一团队能够确认坐标、动作和评测语义是否一致。

本次默认只生成项目和检查入口，不自动调用付费模型、不使能或运动真机，也不自动启动仿真或运行验证。需要执行验证时遵循用户后续指令。未运行的检查明确写“未验证”，不得报告已经跑通。

完成时说明：生成了哪些模块，哪些依赖真实资料尚未接入，下一步最少需要提供什么。即使硬件资料缺失，也交付已能独立使用的核心部分。
