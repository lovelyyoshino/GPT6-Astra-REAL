# PiPER 双臂与三路 D435：实验使用说明 v0.9

2026-10-05用户取消左臂动作，要求只用已归零右臂，并明确允许无标定尝试。独立单臂移动/夹爪入口保留另一臂原模式和使能，仍检查它的健康/静止，不将其名义越界或未使能改写成正常。当前图像和深度可支持带不确定性的候选目标，但深度点仍属于相机坐标；旧近似安装参数、CAD指尖偏移和当前物体位置必须分别标注来源，不能声称完成标定。接近、夹持、轻提核验、搬运、放入、释放及撤离逐段检查。

用户指定六轴回已有0°时使用v0.8独立 `robot_home_arm(arm)`。它是单臂低速返回固定零角度，不是重新设定关节零点，也不修改控制器限位；两夹爪保持，另一臂只读监测。当前关节目标属于折叠附近回零，完整臂体、支架和线缆路径仍需现场审查。仅新反馈到位并稳定且独立复查后，才记录为任务初始位；“零目标误差内”与严格关节范围合法分开报告。

核验日期：2026-10-04。用途：让模型理解硬件、形成动作候选，并让工具在动作前检查依据。
平台已实现通用 SDK 执行器；本站抓取运动入口因保持停止未验证而硬拒绝。另有用户授权的模式接管和重启后关节启动工具；模式/使能可能影响物理状态，不等于观测或抓取解锁。本文不是现场安全认证。

单臂重启后使用固定 `robot_startup_arm(arm)` 的独立准备合同：选中臂必须待机且六关节和夹爪全未使能；另一臂只读监测、保持其原模式及使能状态，不发送命令。只向选中臂各发送一次厂家模式与使能帧，分别核验新反馈；不回零、不闭爪、不改关节零位/限位，不自动重试或失能。其成功不保证关节已合法、夹爪已就绪或任务可执行。原 `robot_startup_arms` 仍要求双臂完整待机/未使能起点。

v0.7.1 的 `robot_prepare_gripper(arm)` 只初始化选中空爪，目标由当前实测开口固定生成（0–70mm），不接受用户目标或力度。它要求选中臂CAN模式及六关节使能，另一臂保持原状态并零TX；严格检查双臂关节/姿态/开口漂移；姿态使用厂家RPY约定下的整体旋转差0.003rad，避免欧拉分量放大造成误拒绝。厂家发送一帧含开口、名义力0.2及使能的命令，可能微调夹指；没有纯使能或保持停止承诺。原双爪准备5mm下限是旧软件合同，不是厂家物理下限。新空爪入口不修复关节越界，也不解除任何任务运动资格。

## 给任务模型的简明摘要

- 两臂各有 6 个关节；每个目标必须注明左/右臂、参考坐标系、末端参考点、位置单位和姿态单位。
- 厂家求解器决定关节解；模型负责动作意图、候选末端位姿、先后顺序、预期结果与不确定性。
- 左右臂基座是两个坐标系，不能把右臂的数值复制给左臂，也不能把相机左右直接当成机械臂的 ±Y。
- SDK 法兰位置不是指尖位置；法兰 Z 高于桌面，仍可能由指尖、腕部相机或支架碰桌。
- 先检查整个动作过程中的臂体、工具、相机支架、线缆与另一条臂；端点可达不代表路径安全。
- 只使用带时间戳的当前观测。图像或深度缺失、被布料遮挡、反馈过期时，相关判断标为未知。
- 衣服会变形、滑动和遮挡；两臂同时抓住衣服后产生耦合，一侧受阻时不能默认另一侧可继续拉动。
- 保持姿态停止未验证时，不启动抓衣任务；单独授权的通用调试仅在各自限定范围内进行。“少发后续指令”不等于停止已接受的运动。

| 数据 | 约定 | 容易混淆的地方 |

可先用图像表达“衣服左上角”等任务关系；没有可追溯依据时，三维位置只能列为模型估计，不能称为实测坐标。
工具应保存参考点与来源，拒绝缺少单位或坐标系的动作表。

## 关节、夹爪与速度边界

下表区分本机厂家 `piper` SDK 预置值与[本轮控制器读回](../runs/joint_limits_dae169c6de344b33b3ab4256bb1a1ec1/result.json)的存储角度限制。J6 存在差异；不能自动扩大 SDK 限位，也不能把存储限位当作碰撞安全范围。

| 关节 | 本机 SDK 预置范围（°，约值） | 双臂控制器读回范围（°） |
| --- | --- | --- |
| J1 | −150 至 +150 | −150 至 +150 |
| J2 | 0 至 +180 | 0 至 +180 |
| J3 | −170 至 0 | −170 至 0 |
| J4 | −100 至 +100 | −100 至 +100 |
| J5 | −70 至 +70 | −70 至 +70 |
| J6 | −120 至 +120 | −180 至 +180 |

预置来源：[本机厂家型号常量与 MDH 参数](/home/agilex/pyAgxArm/pyAgxArm/api/constants.py:43)。不同型号的腕关节范围、MDH 参数不能互换。速度读回原始值为 300，厂家解析为 3.0 rad/s，但消息注释的比例为另一数值；已保留原始数据，未把该速度字段转为执行许可。
执行层应核对型号、固件、零位与控制器限制，保留限位余量；SDK 限幅或夹紧参数不等于原目标执行成功。
AgxGripper 有不同的行程配置，文档列出 70 / 100 mm 选项；现场夹爪型号、指垫和实际行程仍待核验。
新版 `move_gripper_m` 使用 m，`force` 文档标为 N；不能照搬旧版按 N·m 理解的力度数字，需确认本机固件对应语义。
上述夹爪约定来自 [厂家 AgxGripper API](https://github.com/agilexrobotics/pyAgxArm/blob/master/docs/effector/agx_gripper/agx_gripper_api.md)。
历史右爪曾收到 55 mm 张开命令并反馈约 54.32 mm；这只能说明那次开口，不是最大行程或当前状态。
夹爪闭合、开口稳定或电流变化都不能单独证明已抓住衣服；应结合衣物随动和后续图像判定。
速度百分比是控制器参数，不是承诺的 mm/s；小百分比、低质量衣物也不构成碰撞安全证明。

本轮双爪已通过当前开口目标使能，左反馈约 42.84 mm、右约 50.26 mm；衣服尚未夹取。右臂 J2/J3 边界恢复工具原记录 aborted，随后新反馈确认右臂合法稳定；左 J2<0、J3>0 尚未恢复。右臂之后的局部直线试验已实动并发送覆盖目标，但保持停止资格未通过，见下节。

[接管前观测](../runs/obs_93ea0898e3194f7d910df4a554a31ae6/observation.json)已直接取得三路画面及完整双臂反馈，完整下摆可见，双臂使能、无故障、`ctrl_mode=2`、`teach_status=0`。它是有时间戳的历史采样，不是下一次执行时的实时起点。
`can1` 在更早配置中曾绑定示教主臂；当前它绑定已核对 USB 端口的右从臂，不能沿用旧编号角色。USB 再次更换插口、重新枚举后应重新核对身份。
前视相机俯仰曾被调整，旧外参不能继续视为有效；腕相机跟随各自机械臂运动。
D435 是双目深度相机，厂家列出的理想工作距离约 0.3–3 m；RGB 和深度视场不同。[D435 产品页](https://www.realsenseai.com/products/stereo-depth-camera-d435/)
最低有效深度随分辨率变化：640×480 约 175 mm，1280×720 约 280 mm；不是统一的“10 cm”。[数据表 Table 4-11，第 85 页](https://dev.realsenseai.com/download/42003/)
因此，腕相机贴近衣服时即使 RGB 清楚，深度也可能无效；遮挡、边缘、弱纹理或反光处需逐帧检查有效性。
深度零值、空洞不能解释为自由空间；颜色对齐深度也不等于已转换到机械臂基座。
三路相机可各用一个 SDK pipeline 采集，但同时打开不等于硬件同步；记录帧时间、主机时间、帧号和跨相机时间差。[厂家多相机示例](https://github.com/realsenseai/librealsense/blob/master/examples/multicam/readme.md)
相机只观测它看得到的表面。布料下面、夹指背面和两臂相互遮挡的区域应明确列为未观测。

## 预演和停止必须说明实际能力

预演至少核对：观测依据、型号与单位、两臂起点、阶段先后、工具占用空间、共享区域、预期结果和未知项。
预演结果分别报告“格式通过”“运动学已检查 / 未检查”“环境与双臂碰撞已检查 / 未检查”，不能合并为“安全通过”。
本机新 SDK 有离线 `fk()` 和 TCP 转换源码；它们能检查模型一致性，但不能独自证明任意末端目标可达。
`get_ik_joint_angles()` 是特定固件在笛卡尔命令后的逆解反馈，不是接受候选位姿的离线求解函数；不得为取得反馈先发运动命令。
这些能力边界以 [本机 SDK 文档](/home/agilex/pyAgxArm/docs/piper/piper_api.md:3936) 为准，求解能力未接入时明确返回“未检查”。
MOVE_P 的中间路径不能当作末端直线；MOVE_L 的末端直线也不保证肘部、相机和另一只手避障。
新 SDK 的 `electronic_emergency_stop()` 文档仍说明机械臂会以恒定阻尼下降；不能因函数名称变化就认为它保持原位。
已找到协议暂停字段和厂家 ROS 重发当前关节目标的候选办法，尚未在本机验证，不能直接当作可用 hold；来源及边界见 [SDK 审计](SDK_AUDIT.md)。
本轮[右臂局部 MOVE_L 覆盖试验](../runs/linear_hold_2657b6880edc4414b4c2bc9dc347ae1d/result.json)在 1% 速度、空载条件下实际上移约 1.246 mm 后发送当前位置覆盖，先前模式单帧产生的故障 4 消失。但十秒内始终未确认到位，`qualified=false`、`local_hold_observed=false`。[后续观测](../runs/obs_51d6d9e1549e4fa8833416fcce182872/observation.json)右臂反馈位置维持约 +0.364 mm、距覆盖目标约 0.885 mm，仍 `motion_status=1`。该字段表示未到目标，不能直接等同“正在运动”；反馈位置稳定也不能证明缓存目标已取消，更不能推广为通用停机能力。
此前超时后发送旧快速急停，末端参考点下降约 159 mm，已发生险情；见 [原始实验复盘](/home/agilex/piper_right_pick_demo/baselines/model_direct_vendor_ik/INCIDENT.md)。
停止语义依据 [本机新版 SDK 文档](/home/agilex/pyAgxArm/docs/piper/piper_api.md:1656)。普通超时不得自动映射到这种停止。
返回异常或断开 SDK 不保证运动已取消。双臂执行恢复前必须验证明确的暂停、故障、断联和恢复策略。
v0.2 的 paired 动作是近时派发与到位屏障，不是原子事务或同步路径；夹爪仅按目标开口到位判断，衣物阻挡未达目标会超时，不会自动认定抓住。
