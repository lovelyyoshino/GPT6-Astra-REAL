# PiPER X 有界关节路径设计

2026-10-07。六轴关节候选、持久宿主接口、真实 SDK 发送适配与同模式保持桥已写入代码。同连接准备、控制器限位查询、来源读取和独立首次目标初始化已接入服务；官方固定字节纳入版本化数据目录。来源绑定的边界内移已通过离线真实 SDK/FakeCAN 贯通，候选/静态夹持的受支撑释放与空爪撤离也已接入；当前现场几何、带载拔插及其释放接续、RGB 物体进展和目标终态仍未形成完整链路。本文区分模块实现、生产接线和物理结果，不代表实机运动、保持或物体任务成功。现有 [PAIR_HOST.md](PAIR_HOST.md) 的一次只动一臂、双臂监测、唯一 owner、总预算和故障锁存继续适用。

普通空载接近/对齐现已有独立 `rgb_supervised` 分支：当前图像与本体反馈只产生下一有限目标，宿主绑定本次 operation、编码目标和真实缓存，不要求预先实测整段轨迹。初始化与普通动作共用暂态观测计时，发送前检查、发送后有限收敛和最终稳定到位分开；普通视觉取消为 latch_only，不冒称米制保持。准确接口及范围见 [PAIR_HOST.md](PAIR_HOST.md)。
## 结论与官方依据

当前已开始基础实机验证：双爪在原非零姿态按实测开口使能成功，十二关节限位读取成功，三路连续录像完整保存；关节初始化因实际几何来源缺失未派发。后续离线增加 `robot_pair_publish_geometry`，从结构化真实资料导入附件、工作区和本场景净空，减少调用者手填内部字段；它不提供现场测量，也不代表已完成关节／带载试验。实际发送与独立录像审计见 [本段实机记录](../../../artifacts/plug_live_validation_1791357436415587512/live_audit.json)，接口说明见 [持久宿主](PAIR_HOST.md#保持净空与接触能力)。

保留用户确认的两臂物理型号 `piper_x`，增加独立的关节路径合同。通过已知关节目标控制、X 模型计算整臂运动，减少对控制器笛卡尔 IK 的依赖；不把设备改回 `piper`，不拟合一个固定变换后直接执行，也不刷固件或修改零位。

本轮核对的官方 SDK commit 为 `841a625f5f4920e776f20b934eb13048b747e6d0`，URDF commit 为 `f6642ce0d7872c686f29c99e9e10cd23d1d49313`：

- SDK 按 `robot` 选择 MDH；X 使用独立参数，但继承 Piper 的关节、法兰反馈及 MOVE_J/MOVE_L。型号参数没有把控制器内部几何改成 X 的作用。见 [MDH 选择](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/pyAgxArm/protocols/can_protocol/drivers/core/arm_driver_abstract.py#L76)、[X 驱动](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/pyAgxArm/protocols/can_protocol/drivers/piper_x/default/driver.py)、[普通关节编码与反馈](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/pyAgxArm/protocols/can_protocol/drivers/piper/default/driver.py#L126)。
- 固件 profile 由实际版本选择：≤ S-V1.8-2 用 `default`，1.8-3～7 用 `v183`，1.8-8 用 `v188`，≥1.8-9 用 `v189`。公开的 X 符号修正涉及 CPV/MIT，不是普通关节或法兰坐标补偿。见 [官方固件表](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/docs/piper/firmware_reference.md)。`get_firmware()` 会发送查询，不能标为零 TX；优先使用当前宿主已有完整缓存，未获得版本就保留未知。
- [TCP 偏移](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/docs/piper/piper_api.md#L963) 是 SDK 本地的法兰到工具变换，不改变原始法兰反馈。当前快照直接读取厂家解析器中的法兰分片，不能通过 TCP 参数消除这次差异。
- 官方未公布“PiPER X 固定输出 Piper 虚拟坐标”的兼容合同。保存反馈与 Piper FK 的吻合只描述这些数据，不识别物理型号或证明控制器内部配置。

## 模型、坐标与限位

每臂分别保存以下来源，不覆盖原始反馈：

| 数据 | 用途与约束 |
| --- | --- |
| `physical_model=piper_x`、型号来源、设备绑定、固件版本/profile | 身份与协议；型号不从 FK 数值吻合反推 |
| 原始 `joint1..joint6`、rad、分片时间 | 关节命令/回执来源；不静默取反、加零偏或截断读数 |
| `controller_flange_pose` | 保留原始控制器 m/rad、ZYX RPY 遥测；当前几何解释未解决 |
| `model_flange_pose=FK_X(q)`、模型 commit/hash | 显式标为模型推导，用于候选几何计算；不是独立实测末端位姿 |
| 夹爪/附件模型、现场净空证据、有效范围 | 供整臂路径检查；模型不包含现场 RealSense、支架和松弛线缆 |

X 的 [SDK MDH/限位](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/pyAgxArm/api/constants.py) 与 [官方 URDF](https://github.com/agilexrobotics/agx_arm_urdf/blob/f6642ce0d7872c686f29c99e9e10cd23d1d49313/piper_x/urdf/piper_x_description.urdf) 分开固定。J1 为 ±150°，J2 为 0～180°，J3 为 −170～0°，J4/J5 为 ±89°；J6 SDK 为 ±180°、URDF 为 ±120°。已实现的候选模块显式采用 SDK、URDF、带来源的控制器限位三者交集，并将原始差异保留在报告中；整数限位向区间内部取整，不静默选择较宽者。报告这个保守交集不等于解释了厂家两份资料的差异。

本轮做了**纯离线数学对照**：将 URDF 的 `origin × joint rotation` 沿 base_link→link6 组合，与 SDK X MDH 比较零位、一个一般姿态及已保存左右姿态，共四组。旋转差约 `8×10⁻⁸ rad`，位置差约 `0.260 mm`，对应 URDF 最后偏移 `0.035 m` 与 MDH `0.03526 m`。这不是实机精度或标定结果，不能解释保存反馈约 60 mm、1.5 rad 的差异。原始模型及哈希在 [官方资料目录](../../../artifacts/piper_x_capability_review_1791347348345247360/)，保存反馈对照见 [模型报告](../../../artifacts/piper_x_model_compatibility_1791348776025530567/report.json)。

## 候选与准入分流

新合同为 `piper_x_joint_path_context_v1` / `piper_x_joint_path_plan_v1`，实现于 [joint_path.py](../robot_tools/joint_path.py)。旧 `bounded_joint_step.py` 与 `startup_recovery.py` 的 FK/控制器一致性检查仍保留；新合同没有通过修改旧入口来继承其资格。

1. **合法起点的六轴小步，已实现。** `plan_joint_path(context, target_joints_rad, now=...)` 接受明确的六关节绝对目标；J1～J6 均可变化，每轴请求值及编码值相对冻结起点和当前反馈均须 ≤0.025 rad，目标离有效限位至少 0.010 rad。厂家 millidegree 的三种现有换算表达式必须产生同一整数，否则在发送前拒绝。模块不做自动 IK、目标截断或重试；将来视觉方向到关节候选的生成器仍须经过这个入口。0.025 rad 是单轴上限，联合包络、净空和保持余量可能要求更小的动作。
2. **边界起步走独立初始化。** 非零上电本身不是异常。普通 `joint_path` 的 `unloaded_startup_j2_j3` 候选仍未接入其运输层；现在另由 `joint_initialization.py` / `pair_initialization.py` 复用既有受监督 startup 范围，接受明确空载语义、P/J/L 已知模式、J2 下界/J3 上界 ≤0.10 rad 的偏差及已知失能夹爪。目标是最近精确边界，其余轴保留原始值并核对编码误差；采用独立模型/原始反馈，不修改旧绝对 FK 入口。未知旧目标风险继续明示，不要求先有缓存或普通 hold；完成后建立真实首次发送记录。两条合同不能混用。
3. **双来源与整臂包络，已实现。** 用 `FK_X(q_before)` / `FK_X(q_target)` 检查 ≤15 mm 目标端点；原始控制器位姿保留自己的相对漂移检查，不被 FK 覆盖或重新标号。几何包络包含原始/当前关节、调用者目标、编码目标、已知旧目标及三个关节帧更新形成的混合目标，原起点以哈希绑定。整臂、附件、被动臂及保持附加位移共同占用净空，保留现有 60 mm body allowance 与 5 mm reserve。法兰通过固定 X MDH 的全关节区间上界核算 ≤20 mm/0.05 rad 的动作总幅度，并保留原每轴 0.003 rad 保持余量；附件表面位移不混作法兰位移。包络是待监测的有界合同，不保证固件插补绝不超出。
4. **来源绑定的边界内移，已实现。** `joint_ingress.py` 只接宿主从设备 live 记录取得的初始化来源：同 run/owner/epoch/连接、全套有效限位及当前缓存必须匹配，源事件须有完整四帧和完成反馈，新样本须晚于完成记录。仅目标恰在 J2 下界/J3 上界时，允许对应起点和反馈的 0.003 rad 观察尾差；名义限位、目标内侧 0.010 rad、每轴 0.025 rad 及跨步原锚不变，另一臂尾差也须有其自身来源。普通目标替换缓存后该侧旧来源失效；MOVE_L 任意发送尝试同样使该侧 joint 缓存/来源失效，夹爪动作保留关节来源。工具不增加例外开关。
5. **普通 MOVE_L。** 当前型号/FK 一致性、30 mm/0.05 rad 单步及其他 guards 保留。关节路径到位、模型拟合或一次恢复成功均不自动解锁 MOVE_L，也不证明关节插补形成直线拔插轨迹。

## 派发、同模式保持与故障

- 已有 `PairHost/PairDevice` 与 [pair_joint_adapter.py](../robot_tools/pair_joint_adapter.py) 分支，复用 owner、SDK 连接、scene、peer 回执、总预算及 durable event-id。每步固定 1% SDK 速度档；前后各三秒、至少 20 次完整递增反馈，每帧在账本 I/O 后重新读取双臂并核对 50 ms 新鲜度。1% 是指令档位，不是本轮实测速度。
- 一个 MOVE_J 只尝试 `0x151/0x155/0x156/0x157` 各一帧。前三组关节更新及模式激活均非原子提交；已知旧目标的来源必须保留。前一步可由同 owner/epoch/连接的另一已完成 worker 产生缓存，本步不能用新 worker-id 改写旧来源；本步动作到其 hold 则必须是同一存活 worker。未知缓存、部分发送、模式切换均不得以“当前位置静止”替代。
- **同模式保持的软件路径已实现。** [host_joint.py](../robot_tools/host_joint.py)、[pair_ledger.py](../robot_tools/pair_ledger.py)、[hold_transaction.py](../robot_tools/hold_transaction.py) 将明确客户端取消与普通故障分开。仅原四帧完整返回且来源已落盘时，才可在原 worker/连接上预留一个独立 hold 事件，冻结新测目标，再以原总预算发送一次同 J 模式覆盖。数据库后重新采样，细微变化按冻结的 0.003 rad 带及几何预算检查，不要求反馈逐位相等；真实 SDK 的重复模式帧过滤期间只作有限 RX 等待，不关闭过滤或补发遗漏帧。
- 原动作故障始终保留。未知/部分发送、普通故障、EOF、追加独立故障或过期均不产生可复用 hold 许可；新进程不能从磁盘重建可发送事务。取消先软件阻断；专用发布等待最多 25 ms，超时失败不可由迟到提交复活，这段等待不承诺持续 RX 或实时停止。保持帧尝试会使旧缓存资格失效。新模型分支分别保存 X 几何和 raw controller 遥测；旧绝对 FK 一致性分支、普通 MOVE_L 均未放宽。当前硬件适用性还未验证，`physical_stop_verified` 与 `original_target_cancelled` 均保持未知。
- 持续静止、关节到位、保持响应和物体抓牢分别记录。负载支撑、拔插接触及其异常处置没有因这个关节路径而实现；禁止提升现有 contact support/step 能力布尔值。

## 完成双臂插拔的实施路线

目标仍是左臂固定插排、右臂把原孔插头拔出并插入左侧孔位。沿用本现场两插座均已断开市电、两臂为 PiPER X 的确认；记录属于本任务，不转成其他场景永久授权。以下是待逐项接通的执行设计，不是已执行日志。

| 阶段与代码落点 | 可观测验收 | 失败退出 |
| --- | --- | --- |
| **1. 复用唯一宿主与录像。** 沿用同 run/owner/账本和现成 RGB-only 录像 worker；按现有接续入口仅补实际缺失的使能/模式条件，保持一次只动一臂。 | 当前接口与 SDK 连接绑定一致；双臂反馈递增；三路新 RGB 与连续录像属于本轮场景；旧预算未重置。 | 第二发送方、连接变化、反馈失效或录像异常时停止新增动作，记录具体状态；不反复 prepare，不以进程退出证明停止。 |
| **2. 独立首次初始化，软件已接入。** `robot_pair_initialize_joint_target` 复用同连接的受监督 startup 范围，冻结合法当前位置目标或最近 J2/J3 边界；目标/来源由宿主生成，模型仅提供当前空载 RGB 语义。 | 完整四帧、新 J 模式及三秒到位窗口分别记录；仅选中臂已命令的姿态/模式更新，peer 与夹爪原锚保留。首次缓存来自这次真实发送，不来自观测 q 或旧测试。 | 缺实际来源在 claim 前拒绝；部分发送、漂移、超时或反馈异常锁存，零重试。未知缓存激活及非原子更新仍属于明确的监督范围，不报告普通已知缓存证明或物理停止。 |
| **3. 补齐当前 scene 实际来源。** provider 和当前限位采集已生产接线；复用已固定官方机器人参数、当前控制器限位、设备附件资料、当前 RGB 和已有工装/通道证据，绑定 origin/scene/hash。视觉只提出物体方向及候选；六轴候选经过现有 pure planner。 | 模型/控制器/附件/净空来源可追溯；三路图、双臂反馈和独立 peer receipt 同场景；空载小步的方向响应及同模式 hold 分别取得真实证据。 | 官方 URDF 没有相机/支架/线缆时不能补默认尺寸；RGB 像素不能冒充米。来源缺项在准入前报告，不因此宣称设备故障；实际派发后的方向不符或反馈异常按故障处理。 |
| **4. 左臂静态夹住插排。** 用新 RGB 接近/对齐，在原桌面支撑下做一次有界试夹；成功候选经 `retain_grasp` 新三秒反馈升级 `retained_static`。 | 实际闭合响应；图中插排位于左指间且仍由桌面支撑；左侧原目标与锚点保持，插排未被拖移。 | 无响应、位置关系不明确或插排移动则不升级；只走当前适用的明确开爪退出，不加力重试，不声称已能承受拔插负载。 |
| **5. 右臂静态夹住插头。** 左侧静态合同有效时，右侧独立接近/对齐/试夹/保持；两臂各有 episode 和原始锚点。 | 新 RGB 显示右指夹持插头本体、左指仍固定插排；两个新三秒静态窗口与各自原 probe 对应，原插孔仍支撑插头。 | 夹线、夹错物体、遮挡或任一侧漂移时不进入抽出；保留两侧分别的未决状态，不能释放一侧就清空另一侧。 |

| **8. 持物横移并对齐左孔，独立 RGB 分支已接入。** 右臂在完全脱离后沿有界通道搬运，六轴分别受限；新 RGB 用于修正位置与姿态，左臂继续固定插排。 | 原孔保持空置，插头随右指移动而不滑落；插脚方向、左孔位置和进入轴在当前多视角下可辨，电缆未缠挂。 | 目标孔被遮挡、线缆牵拉、相对夹持变化或通道不再成立时退出；关节插补不被宣称为直线轨迹。 |
| **9. 对齐后分段插入，独立 RGB 分支已接入。** 增加插入专用小段及阻挡分类；每段只沿已对齐候选前进，再用新观察决定继续、有限重对齐或退出。 | 插头相对左孔出现预期进入，插排仍稳定，最后可见插头本体就位；没有靠夹爪读数推断电气接通。 | 顶在孔边、偏斜、单侧卡住、插排移动或未确认时不继续压入，不在卡住状态盲目旋转；重对齐也必须是新的有界、经准入动作并消耗原预算。 |
| **10. 右先释放、左后释放，再验终态。** 右侧明确开爪、确认插头由新孔独立支撑后，再释放左侧；每次保持另一臂的当前回执。最后采两次相隔至少两秒的新 RGB/反馈。 | 新孔中插头在双手释放后稳定、原孔为空、插排由桌面独立支撑；两次终态证据期间无后续动作或人工介入。录像和关闭结果分别保存。 | 右释放后物体移动则不继续左释放；松脱、终态遮挡或两次样本不足就不报告成功。后续动作使旧终态失效，需在原预算内重新取证；预算耗尽则报告未完成。 |

首段采用独立 RGB 小段抽出，软件已接入但仍需本任务的实际动作后新图；不能仅把 `contact_support_verified` / `contact_step_supported` 改为 true。若已有反馈包含夹爪名义 force 或电机电流，可保留原值和变化趋势作为辅助诊断，但这里没有新增六维力传感器，也没有电流到轴向牛顿的有效标定；这些字段不能独立证明夹牢、支撑力或插入力上限。

所有阶段共用原任务的动作、时间、无进展预算和一次派发规则。首次接触、接触响应、带载保持、物体进展、独立释放和最终稳定按序记录；不要求未来完成证据先存在，也不把“静态保持通过”直接当成后续带载资格。异常时立即停止新增运动，使用当时已适用的保持/停止机制并读真实回执；没有证据时停止状态为未知，不能用退出、断连或失能补写成功。

## 进一步设计：让整条行为真正可达

### 从当前上电位置开始

“角度不为零”“夹爪未使能”“反馈越出名义限位”分开处理。合法的非零姿态不需要先回零；已连接但缺少空爪准备也不应直接进入整对故障。新增准备模块只解决后者，不移动关节，也不修改限位。真实越界则保留原始角度，先核对单位、型号、固件和控制器限位；不能将读数截断成合法值。

原首目标循环由独立初始化事务解除：新连接缓存仍为 `None`，新实测 q 只成为**将发送的新目标**；独立发送并取得新反馈和稳定回执后才建立缓存，后续普通动作继续检查已有目标来源。厂家 ROS 的当前位置停止按固件分支选择不同模式，见 [官方实现](https://github.com/agilexrobotics/agx_arm_ros/blob/f228cd730a3ea9c1c29af08f66226f79a7a843d1/src/agx_arm_ctrl/agx_arm_ctrl/agx_arm_ctrl_single_node.py#L1063-L1088)；本初始化复用项目已有的独立监督 startup 范围，不把 ROS 示例解释为当前固件的通用停止证明。

这里纠正之前对 SDK 的判断：固定版本 `DriverAbstract` 默认 `_joint_limits_enabled=False`；本项目没有启用该开关。此时 `move_j` 仍经过通用 ±2π 裁剪，但不会把这里小幅 J2<0 / J3>0 的目标自动裁到 PiPER X 的 0 边界。只有显式启用型号限位时才进入型号裁剪分支。见 [默认开关](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/pyAgxArm/protocols/can_protocol/drivers/core/arm_driver_abstract.py#L74)、[关节请求处理](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/pyAgxArm/protocols/can_protocol/drivers/piper/default/driver.py#L126) 和 [通用裁剪](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/pyAgxArm/utiles/validator.py#L103)。SDK 如何编码、本项目是否准入和固件是否接受是三件事；此更正不放宽目标限位，也不证明当前越界目标会被控制器接受。

### 初始化接口必须覆盖实际起点

接口为 `host.initialize_joint_target(event_id, observation_id, arm, unloaded_observation)`，通过同名 `robot_pair_*` 工具接入。目标由宿主按新反馈及固定合同生成；调用者不提供任意目标、旧缓存或 `verified` 布尔值。它只负责第一次目标建立，复用当前 owner、连接、账本、反馈守卫和总预算；普通关节入口继续要求有来源的已完成目标。已有同连接缓存时只观察并返回原来源，不重发或重新标记原事件。

| 当前状态 | 初始化分支 | 接续要求 |
| --- | --- | --- |
| 名义合法、已有同连接完整 J 目标历史 | 直接复用历史 | 不重复初始化，不要求全零姿态 |
| 名义合法、无目标历史、当前 J 模式 | `seed_current`，实测 q 只作为将发送的新目标 | 独立处理未知旧缓存；一次完整发送、新 J 反馈及稳定窗口分别入账 |
| 名义合法、无目标历史、当前 P/L 模式 | P/L→J 首目标建立 | 将模式激活列入同一事务；不先发模式帧等待或伪造 J 历史 |
| J2 下界/J3 上界外、偏差在既有 startup 0.10 rad 内 | 显式最近边界初始化 | 保留原始偏差、已知空爪使能位及另一臂初始异常；仍需通过本分支路径与退出约束 |
| 其他真实越界、未知模式或反馈异常 | 返回具体诊断 | 不通过回零、重连或 SDK 裁剪冒充初始化成功 |

历史快照两臂实际为 CAN 控制、P 模式、关节已使能、夹爪未使能；不能只实现“合法起点 J→J”就称解决了这次启动。依官方 X FK，对该快照仅将 J2/J3 设为最近合法边界，左、右法兰端点变化约为 10.441 / 12.142 mm，旋转约为 0.046112 / 0.010297 rad，均在端点上限内。然而左臂仅 J2 先到边界、J3 未动的组合旋转约为 0.091769 rad，超过普通路径的 0.05 rad；这说明只比较起点和终点会漏掉该合同的路径问题。即便假设共同插补进度，左侧最终 J2、J4 各处在允许的 +0.003 rad 误差时，模型旋转约为 0.052112 rad，仍会超过普通路径的旋转限制。这里均为历史数据上的模型计算，不是当前设备状态或实际轨迹测量；输入哈希、可重放计算及未知范围见 [启动分析](../../../artifacts/plug_startup_analysis_1791354805493798044/analysis.md)。

**合同范围更正：上面的 0.091769 / 0.052112 rad 数值只否定普通 `joint_path` 的整体 0.05 rad 合同，不能据此否定独立 startup。** 原 `startup_recovery` 没有整体旋转 0.05 rad 或已知缓存/hold 门槛；它用每轴 0.10 rad 恢复上限、0.003 rad 跟踪、15 mm 目标及 20 mm 过程位移、整臂相对净空约束和现场监督。新增 X 分支保留这些数值，模型 FK 用于几何及最终 2 mm/0.02 rad 到位，raw controller pose 单独监控相对变化；不声称旧绝对 FK 一致性成立。前后均需三秒/至少二十次反馈推进，逐帧 50 ms。原锚位置和夹爪允许带与 0.5 mm 稳定窗口分开；准备态和 ready 态各自较严格的既有持久锚条件不放宽。四帧非原子、旧目标取消未知的事实保留，软件 cancel 只封锁新发送，不用 reset/失能/补帧作退出。

恢复后的普通接续现由完成事件绑定，保留 `strict_nominal=false` 和实际尾差，不重复发送边界。历史独立轴三角上界在两轴分别进入至少 0.010 rad 内侧时，加入 tracking/hold 余量约为 0.056 rad、22.667 mm，超过普通 0.05 rad/20 mm；这是旧算法的保守上界问题，不是实机超限测量。`joint_model_bounds.py` 现对固定 X MDH 的完整独立关节区间计算法兰上界：位置使用轴到法兰半径的区间上界，旋转仅在模型精确平行轴结构成立时合并区间和；不假定关节同步、不以端点采样替代连续区间证明。保持余量仍用原全局半径，整臂/附件/被动臂净空及 5 mm 余量不变。保存姿态与合成 ±0.001 rad 尾差的最小 573 毫度内移例中，动作加原 hold 预算的左右位置上界分别约 14.17/14.07 mm，旋转约 0.047 rad，均是离线模型计算，详见 [数值与推导记录](../../../artifacts/plug_ingress_1791356964575384710/model_bounds_validation.json)。

**内移观察带不授予保持资格。** `hold_reference_within_nominal_limits` 如实报告原始双臂参考是否名义合法：任一臂原点含边界外尾差时为 false，现有 hold constructor 仍以 `nominal_joint_limit` 拒绝，不能因为选中臂随后已到内侧而重写原点或发送保持。对应取消回归为零 hold 帧、原故障保留、停止未知。两臂均完成内移后的后续普通动作再按其新原点独立判断；该字段为 true 也只是必要事实，不是物理保持证明。

### GPT 如何通过尝试接近目标

原插头、原插孔和用户指定左侧目标孔先在当前 RGB 中冻结身份。切换到腕部视角后仍跟踪同一孔，不能把新画面左侧当成另一个目标。每轮只输入当前阶段、必要图像、本体反馈、上次动作及物体响应，提出一个有限动作；执行器验证并至多发送一次，再取新图决定下一步。合法、已完成的动作没有产生预期物体进展时，可以依新证据生成有限修正；发送结果未知时不能套用这个试错分支。

这不需要预先获得插孔的精确三维坐标，也不需要把所有姿态写成轨迹。但“视觉判断往哪边”和“机器人沿什么路径运动”是两个接口：前者由 GPT 完成，后者仍需执行器。现有六轴小步和端点约束不足以约束插脚的横向扫动。接触段需新增**沿拔插轴的通道、横向偏移及姿态变化检查**，覆盖候选路径和实际反馈；不能把 MOVE_J 称为直线插补。现有 MOVE_L 的型号/位姿解释未解决前，不据此绕回 Cartesian 路径。不新增插座专用 IK/CV，复用机器人通用运动接口及官方 FK 约束。

官方机器人数据自动复用；附件 CAD/已有测量在安装不变时复用，只有变化项更新。物体关系和对齐从新 RGB 判断。用户已给出的净空陈述继续保留，不反复索取尺寸，也不把它换算成不存在的米制记录。严格依赖米制包络的路径仍须有适用来源；这是具体路径所需输入，不是连接、取图或所有接触动作的统一先决条件。

### 接触、负载和退出要一起实现

首次轴向试探的前提是双方静态抓持、原桌面/插孔支撑及适用的有限接触执行器；负载响应由试探后的真实结果产生。不要要求左臂先有承受拔出负载的成功证据才允许首次试探，也不要将第一次通过解释为所有后续幅度的支撑保证。

接触回执至少分开：命令发送事实、关节/夹爪响应、物体相对运动、阻挡/滑移/未确认。健康的受阻状态可能不满足自由空间的目标到位条件，不能直接套用现有普通 move 的成功判据，也不能由模型将超时改写成成功。预期受阻且状态明确时，才有机会经专门合同做新的一次有限卸载/重对齐；部分发送、反馈故障或状态未知仍锁存，不自动反向回放。

PiPER X 已有 `get_motor_states(i)` 的电流、速度和力矩字段，见 [官方驱动](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/pyAgxArm/protocols/can_protocol/drivers/piper/default/driver.py#L584-L615)。SDK 力矩由电流及型号系数计算，见 [官方系数](https://github.com/agilexrobotics/pyAgxArm/blob/841a625f5f4920e776f20b934eb13048b747e6d0/pyAgxArm/api/constants.py#L170)。`arms.snapshot` 已新增可选 `motor_feedback`，直接复制现有六路高速 RX 缓存，分别保留电流 A、速度 rad/s、位置 rad、估算力矩 Nm、接收时间及新鲜度；不发查询、不再次缩放。缺失、过期或读取异常只影响该诊断字段，不改变基础健康/到位合同，也不成为每次任务新的必需前提。该数据可用于后续接触异常趋势设计，尚未接成带载执行器；没有有效外力估计模型时不能将其解释为插入力。低速、小位移本身也不保证峰值接触力，不能宣称现有系统具备精确力控或“卡住一定无损”。

受支撑释放与空爪撤离的软件接续现已实现，范围限于已有 `contact_candidate` / `retained_static`。首次及继续开爪均需当前 RGB 的独立支撑描述：`kind=gripper, operation=release_retreat` 带 `release_support_observation` 和 `release_support_relation="independent_support_present"`。每次最多 5 mm，机械到位只进入 `release_opened`，不丢弃 episode，也不要求先已分离才能继续开爪。最后一次 opening 后的新保存 RGB 与新三秒适配器 trace 经 `robot_pair_confirm_release` 才记 `released`；视觉关系为 `object_clear_of_fingers`、`independent_support_present`，不要求仍在原插孔。

确认后每段 `kind=joint, operation=release_retreat` 需要新图的 `release_retreat_observation` 和当前宿主确认 token；新夹爪 claim 使该侧 token 失效。原关节/位姿锚、另一侧保持、几何和预算守卫不变。未绑定物体的旧 probe 仅清理机械残余；v1 的机械 `released` 不自动获得新分离语义。接口及账本见 [受支撑释放流程](PAIR_HOST.md#受支撑释放与空爪撤离)，离线记录见 [本轮产物](../../../artifacts/plug_release_flow_1791359593200793893/)。此实现不把未来 loaded 状态接通，不证明已插对孔或最终稳定；持物搬运、受力保持/退出、实际现场几何和 RGB 物体进展仍需补齐。

### 把物体进展接到账本

当前 `fast_task_pipeline` 只接受数值 `progress_measurement`，无有效进展阈值为两次；pair 的机器位移回执和 RGB 语义尚未形成可直接接入的物体进展来源。因此 recipe 并没有因为能列出阶段就成为在线闭环。不能拿末端移动距离代替插头分离距离，也不能让 GPT 随口填写 before/after 数字清零无进展。

后续须明确设计独立的 RGB 关系证据类型，绑定前后原图、物体身份、阶段及可见关系变化，分别保存模型判断、不确定性和宿主采集事实；冻结哪些关系变化能推动当前阶段。常规一次提案可同时回顾上一动作和提出下一步，无须额外增加每层模型调用。这是待实现和审查的账本适配，当前数值规则不被悄悄放宽；图片哈希也不认证模型判断正确。无法观察到变化、重复图片或来源不明仍消耗原无进展预算，最终任务证据另行核验。

### 最小交付顺序与验收

| 顺序 | 工程交付 | 本阶段实际验收 |
| --- | --- | --- |
| A | 同连接准备、当前限位来源及 provider 接入；独立首目标建立/必要边界恢复 | 从当前适用非零姿态进入一次合法空载小步，并有真实反馈；不重连、不回零、不循环准备 |
| B | 双侧支持下试夹和静态保持接续 | 左夹插排、右夹插头，两者仍有原支撑；当前图像与分别的反馈对应 |
| C | 轴向试探、接触回执、持物移动、带载保持/有限退出作为一组实现 | 一次可辨认轴向响应；能够区分分离、阻挡、夹持滑动和插排被拖动；异常路径有实际适用回执 |
| D | 抽出、持物横移、重新对齐、分段插入；物体进展到 L3 的来源适配 | 完全脱离原孔才横移；每段观察实际物体关系，对孔不明或顶边时不继续压入；不以机器人位移冒充物体进展 |
| E | 候选/静态状态的受支撑释放及空爪撤离已接通；未来 loaded 接续、任务终态与录像另验 | 原孔为空、插头在目标孔、双爪离开，两次间隔至少两秒的新观测稳定；单个 released 不证明这些结果 |

每次验收先覆盖离线发送/失败分支，再在对应实际任务中取得当前物理证据；历史成功和测试计数不能替代后一项。A 的同连接软件接续已贯通，接下来补实际来源并取得对应现场证据，随后推进 B/C，而不是继续扩大通用检查框架。C 未具备时如实停在具体接口缺口，不把接触尝试换成反复观察。

### 下一轮的具体工程设计

以下增量继续使用共用宿主和操作注册表，不新增插座专用硬件脚本。边界接续和候选/静态状态的受支撑释放/撤离已有软件实现，接下来补视觉进展基础，并把带载动作和受阻退出成组接入；释放实现提前准备，物理执行顺序仍是插入后右先释放、左后释放。

1. **复用已实现的边界内移，补现场证据。** 当前版本以完成初始化事件绑定尾差，以固定 X 模型的完整区间上界核对原位置/旋转预算；同 owner、两连接、原预算的 SDK/FakeCAN 集成已经覆盖初始化、双爪准备、双侧内移及后续普通小步。下一步需要本现场的实际几何来源和动作响应，仍保留部分发送、来源变化、漂移及取消的真实失败分支；含原点尾差的动作不能借 hold 退出。
2. **把首次接触和受阻退出接成一个操作。** 在现有静态抓持上增加有限 `load_response_probe`，把“成功分离、健康受阻、夹持滑移、支撑拖移、反馈未知”作为不同结果。首次试探前要求现有静态接触和原支撑，响应证据在试探之后产生。`healthy_blocked` 只有在新的接触观测合同和可用的有限卸载机制内才能生成重对齐提案；普通超时不能改名为健康受阻。纯夹爪 force、电流或估算关节力矩只作为辅助诊断。
3. **接通可复用带载阶段和视觉证据。** 抽出、持物搬运、对齐、插入分别使用相应通道及物体关系要求；复用每轮一次提案、一次派发。GPT 依据新 RGB 提出有界关节候选和预期可见变化；宿主只用机器人 FK 检查机器人路径，不给模型提供物体真值。视觉证据保存前后观察、对象身份、关系、可见性和 unknown，来源明确标为模型判断；只有冻结阶段规则认可的关系变化才计入物体进展，机器位移不代替它。
4. **复用已接通的受支撑释放和撤离。** v2 episode 使用 `release_pending → release_opened → released`；`release_opened` 可凭新支撑观察继续有界开爪，`released` 由新的分离 RGB 与稳定 trace 建立。其后的关节撤离是独立派发，每段重读空爪新图，不能把 episode 状态当作手已离开工作区或目标终态。另一侧仍保持，右侧完成后再处理左侧；双手离开后才采最终稳定证据。当前不含 loaded 状态的释放接续。

这四组的离线验收必须包含从前一状态真实接续的集成测试，不能直接改内部能力布尔值或注入缓存来绕过缺口。对应实机阶段再记录有限动作后的真实结果；本轮 SDK/FakeCAN 的同连接接续只证明软件路径已打通。


本轮把上述窄范围任务链接入现有 pair 宿主：右臂 `extract_segment → transport → insert_segment` 使用同连接真实目标缓存；首次只需要双侧当前静态抓持与当前 RGB，不要求历史成功运动轨迹。抽出/插入请求与编码后模型目标均不超过 2 mm / 0.01 rad，搬移沿原数值界；这是软件分段策略，不是力控制。固定左臂、双夹爪目标和所有设备守卫保持。详细参数与时序见 [PAIR_HOST 的 RGB 监督插拔有限段](PAIR_HOST.md#rgb-监督插拔有限段)。

每段机器完成后持久记录待新图响应，不能直接继续；源孔完全分离、目标对齐/进入关系由该段后的当前 RGB 建立。局部身体锚只从真实完成回执更新，原抓持锚与累计历史保留；两次累计无进展阻下一段。已接入右先释放/确认、RGB 空爪撤离、左再释放/确认/撤离的软件路径。独立保持观测不认证插排抗拔力，电流没有被换算成腕部接触力；部分发送、异常或未知响应锁存，停止状态仍未知。最终稳定和插到正确左孔仍须实物新图，不由 SDK/FakeCAN 贯穿通过宣称。
