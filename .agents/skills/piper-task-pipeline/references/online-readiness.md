# 在线任务的宿主清理与准备分流

仅在在线任务开始需要清理无效控制进程，或当前状态出现待机、未使能、模式不匹配、缺首次目标或初始化后边界尾差时读取。本流程复用已存在的工具，不为探测新建第二个控制宿主；旧 owner 正常退役后按现成入口接续唯一发送方。不在在线执行中改控制代码、阈值或资格文件。已有有效会话继续使用，不反复验证现成能力。当前任务、总预算、store/run-id 和已确认的现场条件保持不变。

已获用户允许的小幅反馈波动按[反馈波动处理](feedback-tolerance.md)接续：不重复 startup/prepare 消除读数波动。本次右 J4 已有任务绑定的 `right_j4_bounded_v1`（0.5°）实现；本任务接续直接携带已记录的档位和用户陈述。下文未特别说明的 0.003 rad 是严格默认，其他关节及原始平移守卫不变；右臂静止 SO(3) 姿态观察同步使用该 0.5° 档，适用入口与证据见该文。

## 先确定唯一发送方

用当前进程身份、命令行、工作目录、宿主状态接口和独立新反馈识别 owner、设备绑定、活动目标与未决发送。只做变化项诊断。项目内 `runs/execution.lock` 只约束使用同一锁的工具；它不能排除另一个项目的锁、right ROS 节点或旧控制宿主。锁文件存在、PID 旧或宿主故障都不单独证明进程无效。

- 有效宿主仍在执行或保持：沿用其状态/控制入口。需要更换宿主时完成适用的保持交接，确认旧发送方不再控制后才接续。
- 已识别旧宿主失效且空闲：只有独立新反馈确认其涉及的臂全部失能且稳定，新 RGB 确认无持物或接触负载，并且无活动目标、未决或不确定发送时，才可调用该宿主已有的正常 shutdown；先确认此 shutdown 不发送 CAN。保留旧故障锁存、原始错误、发送账本及退出回执；确认旧 owner 退出。旧会话退役不等于清除故障或确认机械臂停止。
- 仍有活动、持物、未决发送或状态未知：不通过杀进程释放控制，使用该宿主适用的停止/保持接口与交接流程。没有适用机制时报告具体缺口，不猜测停止指令。禁止 `killall`、删锁抢占、按历史 PID 杀进程或清 latch 后重发。

宿主/连接确实变更后，只补新 owner 与设备绑定、任务范围所需的当前证据。原故障及未决记录继续保留，不能借新进程重置总预算或重播上次目标。

原窗口到期、当前有效范围正常干净结束且用户明确授权新预算时，按 [干净结束后的显式新轮](audited-restart.md#干净结束后的显式新轮)调用 `pair_round.prepare_round` / `activate_round`；这是保留原历史的独立新轮，不是普通重连续时。用户明确要求“修复后重新计时”时选 `budget_start_policy="after_repair_before_online_execution"`，完成离线修复与检验后、首次在线执行前冻结 `started_at`。一旦起算，后续重连、源码维护和再次修复仍计入该窗口，不自动移动截止时间。

若实际入口在运动发送前遇到代码错误，先正常关闭空闲宿主再修复。仅有成功限位查询历史、从无运动/夹持/保持记录的 run，可用 `robot_tools.pair_ledger.revise_query_only_code_contract` 离线记录代码修订后接续同一 run：它核对旧合同摘要、原始查询帧及计数，实读当前代码并保留旧新合同，原步数、开始时间和截止时间不变。此接口不清除故障、不接管活动 owner、不迁移旧连接来源，也不支持已有运动或持物历史的升级。重新连接后只补新连接需要的当前限位和新图。证据路径与短身份字段分别校验，长目录路径不应被误当成无效动作或缺少实测轨迹。

Piper 断电重启后，重新读取当前控制模式、使能位、关节和夹爪反馈，不沿用断电前的到位或保持回执。若新反馈已明确不满足后续运动入口的关节范围，直接记录具体关节、读数与入口边界；重复使能或空爪准备不能修复该问题，不以这些准备动作冒充任务进展。

仅机械臂断电、电脑未重启的使能分支已接入 `can_enable.sh` 和 `robot_startup_after_arm_power_cycle`。不要再以 Linux boot 未变直接报告不能使能，也不要求为了通过该检查重启电脑。固定工具接收明确的 `arm`、本次 `power_cycle_id` 和 `arm_power_cycle.confirmation(arm)` 对应的实际现场陈述；CLI 根据新反馈自动跳过已使能臂，交互确认只针对待启动侧断电，另记录双臂无持物/接触负载及净空看护。已有明确、适用于本次断电和现场的用户陈述可沿用，不能由模型补造缺失的现场事实。

该分支核对最新有效范围及全部未决/持物记录，不使用 `platform_state(path)` 默认旧根 scope 代替当前轮次。原失败完整发送、当前无控制宿主且现场确认齐备后，由原启动执行器取得新鲜稳定的待机/全失能基线；单臂最多 mode/enable 两帧，另一臂 TX 禁止。原账本追加独立启动 claim，旧 owner、故障、任务目标与预算原样保留；同一事件不重发，新启动失败/未知时不换 ID 重试。成功后下一次实际断电可登记新事件。这个分支不恢复旧坐标、不自动授予任务运动/抓持/停止资格，也不替代关节边界恢复。实现和离线验证见 `artifacts/arm_power_cycle_20261008/validation.json`。

标准机械臂/原厂夹爪的运动学、尺寸和限位优先从对应型号的官方 SDK、URDF 与 CAD 获取，记录版本和来源；不要求用户重复提供厂家已有数据。当前明确型号确认优先于旧记录，PiPER 与 PiPER X 的模型不能互换；修正配置后分别核对控制器反馈与所选模型，旧模型下的 FK/通道结论不自动继承。厂家模型不包含本机自装附件和现场桌面/双臂相对位置。下文附件半径与净空米数是特定恢复算法的输入，不是所有 GPT 视觉小步操作的统一前提；按当前动作选择已适用入口，不能为了省略参数绕过所选入口的守卫。

出现实际型号/FK 不一致时，可在仓库根目录用 `PYTHONPATH=projects/piperx_cloth_demo python -m robot_tools.model_compatibility input.json --output new_report.json` 检查保存反馈。输入 schema 在模块文档中；该入口仅核对官方模型来源、设备/固件绑定、单位及多个姿态的数值关系，不连接设备或修改配置。单姿态拟合不能确认固定变换，额外姿态可以否定已提出的变换；报告中的样本多样性只是诊断描述，不增加通用使能条件。保存数据吻合某个模型也不改写用户确认的实物型号。使能入口自身不要求全零姿态。

## 图像监督步长选择

当前双臂 RGB `joint` 分支按下面的尺度选择一个有限目标。表中长度是机器人官方固定模型计算的本段末端目标位移，不是 RGB 测出的物体距离；上限也不保证在任意姿态或方向都可达到。

| 当前阶段 | 选择方式与当前能力 |
| --- | --- |
| 双爪空载、远离目标的粗接近 | 显式 `motion_profile="coarse_approach"`：v2 每轴目标最多 20°，请求和编码后的模型法兰目标相对原点及当前反馈均须为 30–100 mm（3–10 厘米）；完整关节独立范围及每个反馈样本仍受 120 mm／0.40 rad 过程守卫。 |
| 默认空爪接近、已分离后的持物搬移 | 保留原模型末端目标 15 mm（1.5 厘米）、每轴 0.025 rad 和原过程／保持预算。持物搬移不能借用空爪粗接近档。 |
| 临近目标的接近 | 根据可见间隙选约 5–10 mm；关节或完整过程预算要求更小时继续缩小，不强求走满 1 cm。 |
| 精细对齐夹点或插孔 | 按新图缩到约 1–3 mm，逐段确认方向与物体关系，使用原小步入口。 |
| 最后毫米级微调 | 需要时选约 1 mm 或更小目标；核对编码后的模型步长和实际反馈，不能从目标分辨率推断定位精度。 |
| 专用拔出、插入接触段 | 每段目标最多 2 mm、0.01 rad，结合实际物体响应继续缩小。接触分段上限不用于限制远处空爪接近。 |

每段执行后读取新图与反馈再提出下一目标；不预生成全任务轨迹，不将几个已排队小段算作一个大步。默认档的 20 mm、粗接近档的 120 mm 是过程位移守卫，不能当作目标步长；1% 速度不随步长增大。首次初始化有独立的每轴 0.10 rad 恢复上限，不借给任务接近。当前姿态或方向达不到期望幅度时，报告真实约束，不以缺完整轨迹为由拒绝已有能力内的动作。

粗接近在 `robot_pair_submit_once` 中同时使用 `kind="joint"`、`operation="approach"`、`admission_mode="rgb_supervised"` 和 `motion_profile="coarse_approach"`，在原空载与整臂通道描述外增加 `far_from_target_observation`，描述当前三路图中与目标及障碍物的可见间隙。宿主要求两爪没有未解决的抓持 episode、接触候选或负载；该档不能用于对齐、释放、初始化、带载或插拔。参数写入同一事件并冻结，不能换档重放旧事件。未指定 profile 时完全沿用旧范围。

粗接近 v2 的 20°／30–100 mm／120 mm／0.40 rad 是独立的软件策略，明确扩大了空载接近的动作范围，不是厂家精度或本轮实机认证。仍检查厂家／URDF／当前控制器限位交集、目标内侧余量、请求及编码目标、真实同连接缓存、全部可能的分帧混合关节范围，以及另一臂和双爪、新鲜度与原任务期限。此档仅锁存取消、不发保持帧，因此不另扣不会发送的保持动作预留；原默认档和米制分支的预留不变。发送前仍用严格范围，四帧完整返回后额外暂态带仍为 0.025 rad、累计最多 1 秒，粗档原点上限为 20°＋0.003 rad，最终误差与三秒稳定窗口不变。

v2 替代旧 v1 的 3°／20 mm 档，旧记录保留，但旧计划不能按新限幅重播。远处通道明确时在 3–10 厘米中优先较大可准入目标，临近目标改用约 1 厘米或更小的默认档；需要不足 3 厘米时直接换档，不强行凑足最小粗步。120 mm 是包含关节独立变化和跟踪带的过程边界，不允许请求超过 100 mm，也不是额外可用行程。每段后图像、实测关节与法兰位移分别核对；实际不到 3 厘米如实报告，不自动补发。



本档先完成离线模型、公开入口和 SDK／FakeCAN 测试；这些不代表已经在实机走出厘米级，也不代表插拔完成。执行时以新图和当前有效预算进入，原到期运行不因软件更新而自动续时。

“忽略短暂偏差”在当前实现中指：支持的 RGB 分支在四帧完整返回后，幅度、累计越带时间及其他守卫均合格时记录偏差并继续接收观察，不单凭一次偏差宣告失败、不补发。普通动作的具体范围见下文；带载 joint 段沿用该范围并保留另一臂和双夹爪监测。最终到位仍独立核对。该能力已在代码中实现，不应只停留在模型提示；发送尚未完整、超时或持续偏离不纳入此处理。

候选目标不要只检查名义步长，也要给收敛留余量：普通档原点偏移上限为 `0.025 + 0.003 rad`，请求和编码目标均按当前反馈核对；局部敏感轴可减小目标变化或换用其他关节组合，整段仍由原守卫判断。曾见的读数若已经在当前原点包络外，缩短目标也不能保证覆盖它；不能承诺“留余量”根治反馈问题，更不能在失败后自动补发。2026-10-08 左 J4 的完整 CAN 帧曾报告零值，随后回到目标附近，原因未知；[独立复核](../../../../artifacts/plug_resume_20261008_1625/independent_fault_review.json)区分了普通跟踪带超差与实际原点包络超差，该记录不授予新的噪声许可。

## 遮挡与继续动作

2026-10-09 用户取消“目标遮挡、无法判别即停止”的上层决策规则。`每步新图复核` 指读取并考虑本步新图，不要求每个接触点、两侧夹指和插脚始终完整可见。

- 目标局部遮挡时，物体视觉结果保留 `unknown`。结合当前可见运动通道、任务内已确认的轴向/现场条件、健康且新鲜的关节与夹爪反馈、上步完整执行回执，决定一个现有入口允许的有限目标；证据足以支持该目标就继续，不单凭遮挡请求人工确认或重复采相同视角。
- 物体进展、机器人到位与下一段动作依据分别记录。视觉 `unknown` 不自动变成滑移、卡滞或故障，也不证明抓稳或拔出；原步骤、时间和无进展预算照常执行，不能因遮挡重置或增加。
- 若仍无法确定本段方向/关键运动通道，或反馈显示实际异常，说明具体缺失或异常，不能只写“目标被遮挡”。上步部分/未知发送、陈旧反馈及执行器拒绝按各自原合同处理。
- 当前单左臂 `robot_single_arm_move_once` / 旧控制器兼容分支没有“目标遮挡即拒绝”的程序检查。此前仅据遮挡停止是上层判断过严，本次修正规则即可，不删底层守卫。另一套双臂 `robot_pair_confirm_loaded_response` 的专用物体响应合同没有随此文档修改；不可向它提交虚构的已抓稳或已进展证据。最终任务完成仍需实际结果证据。

## 逐段动作报告与经验更新

在目标计算阶段先说明工作臂、意图和计划幅度：关节目标及相对本次反馈的角度增量，或夹爪目标开口与开合量；已有官方模型预测时单列法兰目标位移。取得回执后，绑定 run/event、来源路径／哈希和采样时间，分别记录实际六轴角度变化、控制器法兰位置／姿态变化、夹爪开口、另一臂变化、实际发送数和到位／稳定结果。模型预测与控制器反馈使用各自来源，不能混成同一坐标真值；按反馈计算的机器人位移不是 RGB 测得的物体位移。

用动作后的新图单独说明物体是否更接近、接触、脱离、插入或仍未变化；缺图、遮挡或不能判断时留 unknown。报告一句“计划—实测—观察—下步修正”，详细数值写动作记录，避免讲解耗尽图像执行余量。一次小关节运动只产生毫米级法兰变化时如实说明，不称走了厘米，也不按单次比值自动放大。下一段仍从新图和反馈选择方向、幅度与原执行上限的交集。经验只保存带来源的可复查结论及适用限制，不复制旧目标坐标、现场授权、接触资格或阈值例外；执行中仅改进判断与技能说明，不自改控制代码、数值守卫或总预算。

## 按当前反馈选择已有准备入口

单臂夹持不以夹爪置零为前提。`robot_single_arm_gripper_once` 的一条普通 `0x159` 目标已含 `enable=1,set_zero=0`，允许六关节已使能、夹爪失能时直接进行已授权的低力试夹；后续独立反馈必须确认使能并稳定。不要先要求退出接触、完成空爪初始化或把负开口修正为零。工作夹爪的目标和实测开口范围仍核对，失能且禁止发送的另一夹爪只保留原始有符号开口、健康和相对漂移检查，不要求它先校准。夹爪稳定但未到目标可作为接触候选，不能自动认定抓牢；试提仍由新 RGB 与反馈决定。

2026-10-09 用户明确要求取消本任务置零前置和无关判别。`maintenance_scope` 将首次任务前、唯一完整发送且无其他动作的失能空爪置零确认失败限制在该臂；原失败及全局账本不删除，只允许另一臂通过已有禁止对侧 TX 的单臂入口接续，每次动作仍持久登记。原请求的已批准反馈档位同时用于锚点及稳定窗口，避免重复的严格窗口否定同一 J4 许可。未知/部分发送、活动 owner、任务故障、对侧意外使能及后续失败仍阻止接续，不提供全局忽略故障开关。

已有 `robot_pair_*` owner 时优先在原连接准备，不调用下表的独立进程工具重新连接。首次需要保留未准备状态时，用长期服务的 `robot_pair_open(connection_mode="prepare")` 零 TX 建立观察；默认 `ready` 保留原已就绪入口。新图显示空爪且该臂已 CAN 控制、六关节使能时，`robot_pair_prepare_gripper(event_id, observation_id, arm, empty_jaw_observation)` 至多发送一次实测开口目标；视觉描述作为语义记录，不是机器证明。动作后取新图再准备另一侧，已使能侧不重复发帧。随后 `robot_pair_promote_ready()` 零 TX 核对原任务条件，保留原姿态锚点；缺条件返回准备需求，不反复升级。

当前控制器限位确实缺少时，在同 owner 下用 `robot_pair_inspect_joint_limits(event_id)`，经 `robot_pair_status` 取一次十二关节查询结果。它无需物体 RGB、允许已知失能夹爪，但仍要求适用的健康、静止、CAN/关节使能状态；十二次查询属于 CAN TX，不是运动指令。完整逐关节原始回复进入同连接来源记录，不修改控制器限位，不建立首个运动目标缓存。工具不接收调用者上传的来源、尺寸或资格字典。准备态尚无同连接待机使能或非 CAN 控制权接管；下述 P/J/L→J 初始化要求已经 CAN 控制、关节已使能，不能代替这些步骤，也不能绕过当前 owner 去开独立发送方。

首次目标缺失时，在原宿主调用 `robot_pair_initialize_joint_target(event_id, observation_id, arm, unloaded_observation)`，用当前保存的 RGB 记录双臂空载、无接触语义；准备态与就绪态均可使用，夹爪可保留已知失能。宿主内部读取带实际来源的官方模型、当前控制器限位及现场几何，冻结自己的新反馈原点并派生目标，调用者不上传目标、缓存或资格布尔值。当前 P/J/L 均可进入 J：名义合法的非零起点建立当前目标，J2 下界/J3 上界外的适用起点按独立 startup 合同恢复到最近边界。沿用每轴最多 0.10 rad、0.003 rad 跟踪带、15 mm 模型终点、20 mm 过程位移、整臂净空、1% 档位、逐帧 50 ms 新鲜度和前后三秒稳定窗口；模型 FK 与 raw 反馈分别保存。普通路径的已知旧缓存、整体 0.05 rad 旋转及 hold 预留不是这个分支的前提。

显式采用图像监督初始化时，给同一工具增加 `admission_mode="rgb_supervised"` 和 `corridor_observation`，具体描述本段双臂整链、夹爪/相机/支架、线缆和桌面的可见运动通道；`unloaded_observation` 仍描述双臂空爪、无接触。沿用用户当前净空陈述，不能把遮挡或不明通道描述为已确认。宿主保存当前三图及哈希、设备/owner/动作身份和原图像期限，读取当前连接的限位；不生成附件半径、米制净空或绝对工作区数据。固定低速、关节/相对位移、反馈、原锚和一次发送限制不变，但此分支明确不提供米制清扫/绝对工作区证明。默认 `metric_geometry` 原合同不变，缺资料不会自动切换分支。当前已接通的图像监督初始化入口只覆盖首次合法种子或最近边界目标，不授予后续普通运动、持物拔插或停止资格；后续阶段必须有自己的适用入口。

图像监督初始化将发送过程与发送后的收敛观察分开：四帧完整返回前仍按原 ±0.003 rad 跟踪带检查；完整发送后只接收反馈，允许起点至编码目标区间外最多 0.025 rad 的暂态，超出原跟踪带累计最多 1 秒。任一相邻样本端点越带就计入整个时间间隔；回带、换关节或重建稳定窗口均不清零累计时间。仍检查原点每轴 0.10 rad、原有效关节反馈边界、raw/FK 各 20 mm、另一臂/夹爪、新鲜度与原截止时间。这里的 0.025 rad 是软件收敛观察策略，不是厂家精度，不扩大目标或发送前范围；默认米制分支仍严格检查原带宽。最终仍须回到目标 ±0.003 rad 和原 FK 到位范围，再通过三秒/至少 20 次新反馈的稳定窗口，才建立缓存。回执记录暂态峰值、累计越带时间和首个失败样本；不因等待收敛而补发目标。

初始化复用原 owner、SDK 连接和总预算；只有四帧完整返回、新 J 反馈与三秒稳定到位后才建立同连接真实目标缓存。另一臂、夹爪和原边界偏差基准保留；部分/未知发送及反馈故障锁存，不补发、不自动 hold 或停止。四帧非原子，未知旧缓存的激活范围仍未获证明，沿用适用的现场监督范围，不宣称硬路径保证或任意动作资格。已有缓存则检查当前原锚反馈，零 TX 返回原来源，不重新初始化；同事件重放只读旧回执。

初始化成功后按实际回执选择下一步。边界到位允许 ±0.003 rad，严格名义越界仍如实记录，不重复发零目标消除尾差。边界向内接续现已接通：仍使用 `robot_pair_submit_once(kind="joint", operation="approach"/"align")` 提交明确六轴目标，无新工具或参数。宿主自动从 live 设备取得完成的初始化来源，核对其原始事件、四帧回执、exact 当前缓存、owner/连接/型号及未变的有效限位；当前新反馈必须仍位于该初始目标的 0.003 rad 带内。仅精确发到 J2 下界/J3 上界的相应关节可接纳该方向的尾差，其他关节及方向仍要求名义合法；缺来源、换缓存或超带不能借此放行。另一臂的来源与原锚也独立核对，不把一侧例外复制给另一侧。

向内目标及编码值仍须离有效限位至少 0.010 rad、每轴变化不超过 0.025 rad。X 模型的新完整独立轴包络收紧保守估计，保留 20 mm 位置、0.05 rad 旋转、原 hold 预留、整臂/附件相对净空及所有新鲜度和一次发送条件；不假设 J2/J3 同步插补，不更改 raw 反馈或 MOVE_L 守卫。这些普通路径限制不反套首次启动恢复。含尾差的双臂原点仍不满足现有 hold 构造入口的严格名义限位：计划字段 `hold_reference_within_nominal_limits=false` 仅报告这一事实，不授予取消后的保持能力，也不阻断此分支已准入的向内动作；异常后阻止新增发送，未知物理停止保留 null。

候选/静态夹持的受支撑释放已接通，不重走启动分流：有身份的 `kind=gripper, operation=release_retreat` 每次需当前图像的 `release_support_observation` 和 `release_support_relation="independent_support_present"`，增量最多 5 mm。机械到位仍为 `release_opened`，可按新图继续有界开爪；最后 opening 后的新保存 RGB 和适配器新稳定 trace 经 `robot_pair_confirm_release` 才记 `released`。之后每段 joint `release_retreat` 要有新空爪描述 `release_retreat_observation`，新夹爪 claim 使当前宿主确认 token 失效。详细语义见 [受支撑释放与微调](../../piper-manipulation/references/bounded-contact.md)；v1 机械释放或未绑定物体的旧 probe 清理不替代新分离确认。

普通空载 `joint` 接近/对齐及确认释放后的撤离已接入显式图像监督：在同一 `robot_pair_submit_once` 上使用 `admission_mode="rgb_supervised"`、`unloaded_observation` 和 `corridor_observation`。前者描述本次工作臂空载且无接触；另一臂可按已有合同静态持夹，不要求它也空载。后者描述本段双臂及附件的可见通道。宿主绑定当前三图、operation、编码目标和真实同连接缓存，从官方固定模型及当前限位读取数值；不生成全任务轨迹或米制现场数值。保持每轴目标 0.025 rad、目标内侧 0.010 rad、15 mm 模型终点、20 mm/0.05 rad 相对反馈及原数值余量；临近目标按新图选更小目标。该分支明确 `hold_policy="latch_only"`，取消/EOF/故障停止新增发送，不派发米制 hold，也不声称物理已停止；默认米制入口及其适用的 hold 合同保持独立。

普通图像监督动作也区分发送中与发送后：四帧完整返回前保留原跟踪带和包络检查；完整发送后才允许有限接收观察，原点至编码目标区间外各最多 0.025 rad，再交原点每轴 ±0.028 rad（原普通最大步长加跟踪带）。超原跟踪带累计最多 1 秒，回带、换轴和稳定窗口重建不清零；最终仍需目标 ±0.003 rad 与原三秒/20 次稳定反馈。新接收观察范围不冒称原发送包络证明，原有效关节界、raw/FK 各 20 mm/0.05 rad、另一臂、夹爪、新鲜度与截止时间逐样本检查。初始化的 0.10 rad 恢复范围不用于普通动作；完整发送历史也不等于物体任务成功。

先完成候选计算、计划幅度说明和准备，再取本段图像；查看后紧接 observe 与单次 submit，不把记账、解释或无关读取插在图像与发送之间。RGB 初始化及 joint 分支在 claim 前要求严格大于 12 秒余量（3 秒基线、6 秒运动及调度、3 秒最终稳定）；普通/带载 joint 首帧前还要求严格大于 9 秒。返回 `refresh_required` 时没有发送或消耗动作次数，只刷新图像后重新判断本步，不重新 prepare 设备。已经 claim 后余量不足仍保留失败及预算，不自动重发。这个最低余量依据已观察段耗时增加运动空间，并不保证覆盖完整 20 秒最大观察等待；原 30 秒 RGB 期限、50 ms 本体反馈和真实超时锁存保持。完整发送后遇到唯一 RGB 到期故障时，按[审计接续](audited-restart.md)选择仍在原预算内的接续，或已到期且用户明确要求重新开始的新轮，不能直接重发。

普通 joint 适配器先完成可能阻塞的持久 guard，再取新反馈立即校验，最后写原样本日志；日志返回时间不充当采样时间，三秒稳定窗同时检查墙钟与实际采样单调时间跨度。原 50 ms、逐帧守卫和故障锁存不变，不用重采或重试替换失败样本。一次性 RGB 到期接续不覆盖零发送的新鲜度故障；已完成调度修复且符合精确历史条件时，另有独立一次的[零发送审计接续](audited-restart.md#原预算内的零发送新鲜度故障接续)，仍用原 run、原期限与剩余次数。离线修复本身不清故障或恢复发送。

米制分支仍按其合同核对现场几何来源；专用 RGB 带载段、逐段物体响应和释放已接入，最终双爪离开及稳定仍由实际任务证据确认，见 [初始化设计](../../../../projects/piperx_cloth_demo/docs/PIPER_X_JOINT_PATH_DESIGN.md#初始化接口必须覆盖实际起点)。新释放入口不改变已到期 run 或缺现场资料的事实。官方 SDK/FakeCAN 的贯穿测试不等于现场资格或物理成功。固定 SDK 的型号限位裁剪默认关闭，仍有通用 ±2π 裁剪，当前小幅 J2<0/J3>0 不会被该默认层裁到 0；代码准入、SDK 编码和固件响应分别诊断。

现有快照可带六路 `motor_feedback`，直接复用 SDK 接收缓存中的电流、速度、位置和估算力矩及各自新鲜度；这是可选诊断，缺失不新增准备或动作门槛。估算力矩不等于外部插入力，不代替物体 RGB 响应或带载执行回执。

首次目标初始化的反馈调度已与普通 joint 分支一致：完成持久 guard 后采样，立即检查原 50 ms 时效与数值守卫，再写入原样本日志。稳定窗口按实际采样墙钟及单调时间均不少于三秒、至少 20 次独立递增反馈计算；日志时间不会给旧样本续期，离开窗口及发送前另取新样本核对同一窗口。校验本身超时、样本陈旧、漂移或取消仍失败，不用再次采样替代一个已被拒绝的样本。诊断包含各阶段耗时；首次补齐的离线验证及实际零 TX 失败来源见 `artifacts/initialization_schedule_20261008/validation.json`。代码修复不清除原故障或自动续发。

startup、接管或夹爪准备返回成功后继续判断本次操作的已有执行入口与现场条件，不因为先前未使能就终止。失败保留原始错误；只诊断实际失败项。部分/未知发送停止新增派发，不自动重试或换 provider 重发。使能成功不修复关节越界，不证明整臂路径可用、保持有效或物体任务完成。

非零姿态可以满足 startup 合同，不要求先回零。区分动作入口的 SDK 名义关节范围、控制器保存的限位和当前硬件报警；某轴的 0° 区间边界不是使能零位要求。用户质疑边界适用性或出现配置差异时，可按已有 `robot_inspect_joint_limits` 合同作一次厂家限位查询，保存新鲜回包和单位。该查询入口要求两臂 CAN 控制且六关节已使能，不能在待机时盲调用；它只读取配置，不修改限位，也不会自动替换动作入口的 SDK 预设。无报警、使能成功或查询范围更宽均不单独证明运动路径可用，不改读数、零位或阈值来绕过拒绝。

2026-10-07 用户明确要求修改严格反馈边界后，`robot_single_arm_*_once` 已分开名义范围和反馈观察带：普通反馈允许 0.003 rad 边界偏差；不发送臂目标的夹爪动作还可保留起始 J2 下界/J3 上界不超过 0.1 rad 的静态偏差，继续执行原稳定与漂移检查。这是新增软件策略，未经实机资格验证，不是厂家精度或零点修正；原始越界和 `selected_arm_strictly_within_limits=false` 保留。例外冻结于当前单步，不能据此宣称跨调用偏差可持续扩大。较大移动偏差返回 `boundary_recovery_required` 和仅供诊断的边界候选，现成恢复步长/FK/整臂通道仍可能不满足；不循环 prepare、不自动恢复，也不把夹爪例外用于 MOVE_L。准确字段见现成工具合同。

用户要求修复非零启动角度后，现成 `robot_recover_joint_boundary` 增加显式 `recovery_profile="startup_j2_j3"`：仅 J2 低于下界/J3 高于上界最多 0.10 rad（约 5.73°）可恢复到最近的原名义边界，其他轴保留 0.003 rad 反馈带；默认 `standard` 仍为 0.05 rad。此恢复合同适用于空载、无接触状态，不作归零校准。两臂关节均须已使能；夹爪允许保留已知失能状态，不为此额外发夹爪指令。每次三秒前置稳定、50 ms 新鲜反馈、1% 速度、15 mm FK 终点和四帧白名单仍由宿主执行。

新 profile 必须带当前 `attachment_radius_m`（覆盖两臂法兰外的全部附件）与 `available_clearance_m`（外界、另一臂和非相邻自身实体之间的最小表面净空，不包括本就连接的铰接/刚性安装面）。宿主要求两倍整臂跟踪包络并计入另一臂微小漂移后，仍留 5 mm 余量；15 mm 末端位移不能替代此条件。不能从旧实验复制这些数值，也不能从无尺度 RGB 编造精确米数。当前来源足够则直接使用；缺失时只补这项现场信息，继续独立离线工作。四帧并非原子提交，未知缓存或半帧混合目标不在该包络证明范围内，仍需现场看护；失败停止新增发送，断连不等于已停止。恢复反馈成功与后续任务准入分别记录，不自动循环恢复或重置任务预算。

夹爪实测开口不在该入口范围内时，区分反馈/零位问题与能力缺失，保存实际读数和零发送拒绝，不循环 prepare、不改成范围内的假读数，不借普通任务自动重设夹爪零位或放宽准备范围。

用户手动调整后按新 RGB 与反馈接续，调整本身不证明夹爪零位或校准完成。

## 当前可用 CLI

缺当前几何来源时，已有实际安装／测量记录可通过同宿主的 `robot_pair_publish_geometry(observation_id, record_set_id)` 导入。只传当前场景和固定资料集 ID；owner、连接、哈希及保守边界由宿主处理。它不采集尺寸，也不把用户定性净空或 RGB 猜测写成米数；实际资料缺失、过期或安装不符时保留具体缺项。记录格式及范围见 [持久宿主](../../../../projects/piperx_cloth_demo/docs/PAIR_HOST.md#保持净空与接触能力)，不要让用户手填宿主内部字段。

同一有效连接沿用当前来源目录中的已有记录。owner 或任一侧连接变化时，provider 自动选择独立来源目录，保留旧记录；新目录需当前连接的实际限位采集和当前场景资料，不能复制旧值改绑。旧索引仅在身份精确匹配且新目录尚未建立时兼容读取；首次新目录发布不会带入旧目录的其他来源，不是透明升级。目录选择不查询硬件，也不继承准备、目标缓存或现场资格；不要为每步新 RGB 重建连接或重复查询。

实机段发现缺口需改执行代码时，先正常结束无未决动作的会话并封口录像，保持原日志、预算和故障事实。纯查询历史可按其原合同做离线代码修订；完整初始化暂态失败且到期的窄场景另有[显式人工授权的审计接续](audited-restart.md)，不适用于部分发送或持物故障。关闭不暂停总时限，来源分目录也不续期，不能换 run-id 清预算。基础准备通过与后续关节／带载动作分别报告。

优先通过已运行宿主提供的入口调用。以下是 `robot_tools.server` 的准确单次调用形式，工作目录、模块来源、`--root`、配置和解释器必须与本次唯一控制宿主相匹配。`--call` 会创建本地 ToolService；没有确认旧 owner 退出及当前发送方唯一前，不使用这些命令新建第二个发送方。原项目仍运行的宿主应按其环境接续，不能仅把路径换为迁移目录便继承资格。

在当前宿主对应的 `piperx_cloth_demo` 项目目录运行；不要把下面的可选分支顺次全跑：

```bash
/home/agilex/miniconda3/envs/pi0_infer/bin/python3.10 -B -m robot_tools.server --call robot_read_state
/home/agilex/miniconda3/envs/pi0_infer/bin/python3.10 -B -m robot_tools.server --call robot_observe --arguments '{"include_depth":false}'
/home/agilex/miniconda3/envs/pi0_infer/bin/python3.10 -B -m robot_tools.server --call robot_startup_arms
/home/agilex/miniconda3/envs/pi0_infer/bin/python3.10 -B -m robot_tools.server --call robot_startup_arm --arguments '{"arm":"right"}'
/home/agilex/miniconda3/envs/pi0_infer/bin/python3.10 -B -m robot_tools.server --call robot_request_can_control
/home/agilex/miniconda3/envs/pi0_infer/bin/python3.10 -B -m robot_tools.server --call robot_prepare_gripper --arguments '{"arm":"right"}'
```

`right` 是参数形式示例，按当前任务所需臂选择，不能凭示例改变角色。系统 Python/ROS 继续用于现成 ROS 宿主，`pi0_infer` 用于上述工具及 RealSense；单个解释器缺包不代表整机无能力。保持 RGB-only，不调用深度定位。

工具细节以 [现成工具合同](../../../../projects/piperx_cloth_demo/docs/TOOLS.md) 和当前宿主代码为准。通用 recipe、账本及双臂离线契约仍为 `offline_contract_only`、`execution_available=false`；这不否定上述真实准备能力，也不赋予它们双臂拔插执行能力。需要固定物体的臂是任务臂；后续两臂交替动作仍需每次另一臂的当前独立保持回执。

## 限位查询的相同回复

同一请求窗口内、同臂同关节且完全相同的 `0x473` 重复数据保留首条数值和有界重复 RX 记录，不再仅因重复而判故障。窗口、查询次数和时限不延长；内容冲突、错误身份或标志、晚包和数量超限仍拒绝。旧版本已经产生的故障不能改写为成功。

本轮唯一事件仅发出一个完整限位查询、全部执行器命令为零且准确符合该重复数据案例时，先保留失败、关闭状态及宿主实际退出证据。修复离线通过且有新的明确用户计时授权后，管理员可用 `pair_round.prepare_round(parent_kind="query_duplicate_fault", budget_start_policy="after_repair_before_online_execution")` 与 `activate_round` 登记新轮，只继承未用派发额度。旧 run、事件、故障和原期限保留，新轮不继承限位、连接、缓存或运动资格。此分支不覆盖部分或未知执行器发送，不是宿主自动重试。

## 录像生命周期

用户要求任务录像时，在实际操作启动前复用已有 `ContinuousRGBRecorder` / `right_pick.fast_camera_worker`，由唯一相机 owner 持续记录三路 RGB；已在录像则接续该 worker，不再开第二个相机 pipeline。worker 只接受 `--config <当前相机配置JSON> --output <本轮新目录>`，配置必须包含且仅包含 `front`、`left_hand`、`right_hand`；使用当前相机环境及已绑定设备。通过同一 worker 的 stdin 发送独立一行 `{"command":"capture"}` 取得同一录像流的新观察，不额外调用会重新占用相机的取图入口。任务完成或因故障退出时发送 `{"command":"close"}` 正常封口，核对进程退出结果、录像 `report.json` 的状态/错误、三路帧数、时间范围和丢帧记录，再分别报告录像覆盖与物体任务结果。录像开始前未录到的过程不得补称已录像，正常 close 也不等于物体任务完成；用户要求“完成后提交代码”不改变任务完成标准，也不扩大控制或删除权限。

专用带载 `extract_segment` / `transport` / `insert_segment` 及 `robot_pair_confirm_loaded_response` 按 [L2 接触与微调](../../piper-manipulation/references/bounded-contact.md#图像监督拔出搬移与插入) 执行；不重走 startup，不冒称力控或停止。

## 校验计算与反馈年龄

若回执是 `Joint feedback exceeded 50 ms including validation`，先读 `joint_validation_timing`，区分反馈入场年龄与本地计算耗时。粗接近的整盒几何由完整不可变数值输入作为键，只在准入时计算并有界缓存；逐样本仍核对完整计划哈希、实时状态、反馈时间和最终发送条件，不缓存图像结论或动作许可。不要因重复静态计算造成的超时扩大运动范围，也不把反馈延迟当作关节跟踪尾差。

当前显式轮次若仅最后一个空载 RGB joint 在任何总线尝试前因该精确错误失败，前序事件均完整、当前无持物/接触且有故障后的三路 RGB、双臂被动静止反馈和正常资源关闭回执，可离线调用 `pair_round.prepare_round(parent_kind="zero_tx_freshness_fault", budget_start_policy="preserve_parent_deadline", recovery_evidence=...)`。`max_steps` 必须等于原剩余次数，`started_at + max_duration_s` 必须等于原截止时间；`activate_round` 记录用户修复接续指令 `authorize_repaired_continuation`，旧故障及所有旧行保留。此管理接续不发硬件命令、不重放失败目标、不清故障；新宿主取得自己的图像、反馈、限位及目标缓存后重新判断本段。部分发送、未知结果、其他故障及带载状态不适用。

## 三小时任务预算与周期效率

`can_enable.sh` 已完成旧状态归档、且本次双臂 startup 成功后，首次全新任务可用 `startup_reset.enroll_task_budget` 显式登记 1000 步／10800 秒预算。要求当前仍无新任务行、owner、未决发送或新故障；之后以同一 run 的 `prepare` 打开宿主。登记开始计时，不重复登记、续时或继承旧坐标；现场存在尚未解决的夹爪反馈等问题时不提前消耗新窗口。接口和记录见 [首次任务预算](../../../../projects/piperx_cloth_demo/docs/PAIR_HOST.md#2026-10-09-软件重置后的首次任务预算)。

新离线任务默认总预算为 10800 秒、1000 个周期、最多 1000 次模型提案；阶段预算和无进展退出仍有效。已有离线任务沿用冻结预算。持久双臂宿主的显式新轮／新预算入口允许 `max_steps=1000, max_duration_s=10800`；普通打开默认值不自动扩张，旧运行也不因升级而续时。按现有管理入口绑定实际任务和用户指令，沿用同一账本及绝对截止时间。这里的 1000 是宿主事件／离线周期上限，准备、失败或不确定派发按原合同计数，不是电机伺服频率或保证运行满三小时。

减少周期优先靠远处较大合规单段、同一控制宿主与来源缓存、每周期一次提案、按 current 只读当前阶段，以及避免已就绪设备反复准备。每段后的新图与反馈、最终稳定窗和接触证据仍保留；不能排队多段、延长图像寿命或减少监测来制造提速。尚无本轮实机耗时收益测量。

用户明确选择：20° 仅用于伴随 3–10 cm 平移的远处空载粗接近；不为平移不足 3 cm 的单独转向开放粗档。关节角上限不是末端欧拉角增量，且多轴同时变化仍须通过完整关节盒与过程姿态检查。

用户要求近处逐步精细到毫米：上述 5–10 mm → 1–3 mm → 约 1 mm 或更小是按图像与阶段选择的尺度，不是提前排队的动作序列，也不是 RGB 测距。近处不使用 3–10 cm／20° 粗接近档。现有 ordinary 入口没有强制最小平移量，量化和姿态可能改变实际可实现步长；原最终到位容差不因选择毫米目标而自动变小。若新图或反馈无法确认微小进展，保留 unknown，不将容差内到位写成毫米级物体定位成功，不自动补发或为凑进展放大目标。
