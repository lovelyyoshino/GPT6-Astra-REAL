# 接近超时后危险下落的复盘

本轮未抓到方块，用户报告机械臂向桌面戳。日志和录像显示，快速下落出现在接近动作超时、程序发送厂家快速急停之后，而不是预定下降抓取阶段。将这种停止方式用于普通超时处理，是执行器的安全缺陷，不能主要归因于没有标定。

## 安全检查缺失在哪里

1. 本次 MOVE_L 平均净速度约 0.451 mm/s，40 秒期限与实际进度不匹配。速度偏慢的底层原因尚未查明；不能只通过延长时间或提高速度恢复运行。
2. 执行器把快速急停用于尚在运动的普通超时，未验证该动作能保持姿态。已有厂家警告并未被充分落实为停机策略约束。
3. 工作区只检查 SDK 参考点，不能代表夹指、相机支架、线缆和整个机械臂与桌面的距离；低速和可解位姿都不是防碰撞证明。
4. 进入停止监测后只记录反馈、检查状态和稳定性；没有能够阻止重力下落的已验证机制。电机码仍为 64、错误码为 0，也不能证明机械臂正在安全保持。
5. 两路相机只录像，没有在线图像判险或模型反馈参与控制。本轮不是实时视觉伺服，也未提供视觉安全闭环。

23 项离线检查验证了模拟反馈下的逻辑，无法验证机械臂在停止命令后真实的受力和姿态保持。不能把它们称为实机安全验证。

## 已采取的处理和恢复条件

当前工作工程已设置 [执行暂停记录](evidence/vendor_execution_hold.json)，自动入口在打开 CAN 或相机前拒绝运行；[验证日志](evidence/execution_hold_check.log) 保存了这一结果。实际运行过的代码、计划和原始数据全部保留，源码哈希与运行时记录一致。本次整理没有发送任何机械臂指令。

恢复前应先核实并验证能保持姿态的暂停或中断方式，明确工具参考点和桌面安全间隙，再核对 MOVE_L 速度与超时语义。不能把复位、失能、断开通信或此处的快速急停默认当成无下落的安全保持；归档代码不得原样重放。

任务仍可以由模型一次规划完整过程，执行层持续读取状态并按已验证的规则中断。完整规划与持续安全监测可以并存，不必把每个运动段都变成一次模型重新决策。具体停止和恢复机制尚未完成验证，本归档不提供新的实机试验命令。
